# WorldWeaver

WorldWeaver 1.1 открывается как чат внутри Unity: **Tools → WorldWeaver → Чат**. Напишите задачу обычной репликой. В верхней части выбираются модель и глубина работы, слева сохраняется история, внизу находится поле ввода и меню **+** с примерами задач. Enter отправляет сообщение, Shift+Enter добавляет строку. Кнопка «Остановить» прерывает ожидание модели; уже исполненные изменения сохраняются.

## Локальный запуск

Проверяемая среда — Unity 6000.3.27f1 LTS. Установите Ollama из официального источника, запустите сервер `http://127.0.0.1:11434` и загрузите `qwen3.5:9b` и `embeddinggemma`. Начальная модель чата — Qwen3.5 9B, режим «Баланс». Более лёгкие `qwen2.5-coder:latest` и `qwen3.5:2b` можно установить и выбрать отдельно. На Mac с 16 ГБ полный цикл 9B может занять несколько минут; строка состояния показывает прошедшее время. Каталог чата показывает установленные completion-модели, а embedding-модель используется для знаний NPC. Ключ и облачные токены для локального режима не нужны.

Для первого собственного мира откройте пустую сцену и напишите: «Создай лесную долину 160 на 160 метров с озером, 12 деревьями, 3 домами и 4 камнями». Затем: «Уменьши высоту этого рельефа до 24 метров». Созданные миры и элементы получают маркер владения; изменения по следующим репликам используют текущие ID сцены. Детали окружения собраны из оригинальной геометрии и примитивов, без скачивания 3D-ресурсов.

Запрос «Добавь осторожного стража Игната, который знает, что северные ворота открываются в шесть утра» создаёт видимого персонажа, IntelligentNPC, инвентарь, отдельную базу знаний и маршрут выбранной модели. В Play Mode появляется панель настоящего диалога с созданными NPC. Установленная цель сама по себе не создаёт произвольную игровую механику: для физического патруля нужны точки встроенного поведения либо подготовленный скрипт; NavMesh-маршруты требуют подходящей сетки.

## Режимы и изменения

«Быстро» ограничивает работу одной итерацией, «Баланс» — тремя, «Глубоко» — шестью. Они регулируют предел шагов, объём контекста сцены и локальный лимит ответа; число параметров модели выбирается отдельно. У бесплатного облака `max_tokens` остаётся не более 1500 во всех режимах: «Глубоко» увеличивает бюджет контекста, раундов и ожидания, но не длину отдельного облачного ответа сверх этого предела. Общий предел ожидания — 2, 4 и 8 минут соответственно. Новые Point/Spot при создании по умолчанию поднимаются минимум на 3 метра над рельефом и водой под их XZ. `on_terrain=false` сохраняет точные XYZ; существующий свет перемещается таким способом только при явном `on_terrain=true`. Это начальное размещение, последующая правка рельефа не привязывает свет к поверхности автоматически.

Более крупная локальная модель требует больше памяти и может отвечать заметно медленнее. Выбранная модель назначается новым NPC; существующие персонажи сохраняют прежний маршрут.

При включённом автоматическом применении разрешённые инструменты изменяют сцену после проверки всего плана. Можно выключить автоматическое применение и просматривать планы. Ошибка инструмента откатывает пакет и его новые ассеты. Обычный Undo Unity отменяет последнее действие, включая ручное; успешно созданные ассеты могут остаться в Project. Чат не очищает активную сцену и сохраняет её отдельным инструментом только по запросу.

C# всегда выводится черновиком для просмотра. После «Применить» файл импортируется в `Assets/WorldWeaverGenerated/Scripts`, Unity действительно компилирует его, а результат появляется в истории. После успешной компиляции отдельной репликой можно подключить скрипт к объекту. Ошибки передаются следующему запросу для исправления. Просмотр кода не является песочницей: применённый MonoBehaviour выполняется с обычными возможностями Unity.

После импорта или восстановления блок исходника остаётся доступным в истории как сохранённый снимок. Его можно раскрыть и скопировать; он не подменяет текущее содержимое файла и не применяет код повторно.

Для доступного сохранённого импорта кнопка **Вернуть предыдущий код** появляется в том сообщении, которому он принадлежит. Она восстанавливает прежние файлы либо удаляет вновь созданные и запускает повторную компиляцию. Если файл после импорта изменён вручную, автоматическое восстановление сохраняет эти правки. Кнопка **Отменить действие** в заголовке использует обычный Undo Unity для изменений сцены и не заменяет восстановление исходников.

## Дополнительные возможности

Прежние WORLD/NPC/KNOWLEDGE/MODELS/DEBUG находятся в **Advanced Inspector**. Готовый пример торговли и небольшой NavMesh создаёт **Create Demo in New Scene**. Действие GiveItem меняет реальные инвентари только после детерминированной проверки; NPC может торговаться или отказать. Самостоятельное планирование использует отдельный набор разрешённых действий.

Бесплатное облако Pollinations Classic — отдельный необязательный выбор модели. Запрос и отобранный контекст проекта передаются внешнему API. На 31.10.2026 сервис задаёт один бесплатный ответ за 45 секунд на IP и предел `max_tokens=1500`; клиент выдерживает между началами запросов 46 секунд. Доступность и квоты зависят от сервиса. При HTTP 402 ограниченно повторяется только ответ с кодом `FREE_LIMIT`; обычное требование оплаты и HTTP 400 не повторяются. Покупок адаптер не выполняет. Для конфиденциального проекта выбирайте разрешённый маршрут. Профили хранят имена переменных окружения, а не секретные ключи.

Classic вызывается в текстовом режиме с явным контрактом JSON-экземпляра. Ответ проверяется в C# до исполнения; гарантированное серверное соблюдение JSON Schema не обещается. Диагностический replay сохранил повреждение JSON Object Mode, отказ native schema по `propertyNames` и успешный текстовый вариант одного проверочного ответа. [Текущие пределы Classic](https://github.com/pollinations/pollinations/blob/73311dad9465c7ddd0ceb9cdc0f2ab8b171f6dbb/text.pollinations.ai/cloudflare-cache/src/origin.js#L24-L27), протокол проекта `results/pollinations-classic-schema-replay.json`.

Для совместимости Classic клиент может добавить ровно одну пропущенную корневую `}` при полностью закрытых вложенных структурах и строках. Затем выполняются прежние проверки всего контракта и инструментов; недостающие поля или команды не додумываются. Исходный и нормализованный ответы сохраняются раздельно. Обычный текст допускается только для распознанной явной просьбы «только объясни», с пустым списком действий. Такая просьба запрещает изменяющие инструменты, включая новые черновики кода; распознавание ограничено явно поддержанными формулировками и не является общим анализатором намерений.

Текстовая история чатов хранится в UserSettings и исключена из Git. Память игрового NPC ограничена сеансом, отдельной системы сохранения игры нет. Голос, PDF ingestion, генерация ригов и полная замена разработчика не входят в подтверждённые возможности. Тесты, реальные протоколы и ограничения сравнения с Unity Assistant приведены в корневом README и docs/research.
