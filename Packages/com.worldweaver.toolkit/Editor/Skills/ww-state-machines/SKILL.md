# FSM или дерево поведения с явными переходами и обработкой отмены

## Рабочий подход
1. Для малого набора взаимно исключающих состояний начни с FSM. HFSM или BT нужны при реальной вложенности и повторном использовании поведения.
2. Определи Enter, Tick, Exit и владельца перехода. Таймеры, навигация и подписки очищаются в Exit, даже при прерывании.
3. Проверка: каждый переход имеет условие, недопустимый переход не повреждает состояние, повторный Enter не дублирует действие.

## Доступные действия WorldWeaver
При необходимости вызови discover_tools с names: create_npc,update_npc,configure_npc_ai,set_navigation,validate_world. Это ссылки на существующие команды, а не разрешение на их автоматическое выполнение. После создания читай реальный target, затем применяй зависимые действия отдельным шагом.
