# Разделение систем и владение данными при проектировании игры

## Рабочий подход
1. Отделяй доменные правила на чистом C# от сцены, авторских данных и представления. Выбирай минимальную архитектуру под масштаб проекта, без обязательного DI или глобальной шины.
2. Укажи владельца состояния, точку запуска и порядок инициализации. Не полагайся на случайный порядок Awake соседних объектов.
3. Проверка: повторный запуск сцены не создаёт дубли менеджеров; отсутствующая зависимость даёт понятную диагностику.

## Доступные действия WorldWeaver
При необходимости вызови discover_tools с names: read_script,draft_script,patch_script,attach_script,inspect_component,add_component,set_component. Это ссылки на существующие команды, а не разрешение на их автоматическое выполнение. После создания читай реальный target, затем применяй зависимые действия отдельным шагом.

## Граница применения
Это справочный Markdown для встроенного агента WorldWeaver. Используй только объявленные в текущем запросе инструменты и их фактические схемы. Навык не добавляет shell, сеть, доступ к секретам, новые разрешения или автоматическое выполнение кода. Если операции нет, дай совет либо подготовь C# для просмотра в поддерживаемом процессе; не выдавай совет за выполненное действие.
