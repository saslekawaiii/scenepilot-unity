# Короткая запись архитектурного решения и проверяемых последствий

## Рабочий подход
1. Запиши конкретную проблему, ограничения, выбранный вариант и отвергнутые реалистичные альтернативы.
2. Отдели измеренное основание от предположения. Не объявляй решение универсальным правилом для всех будущих механик.
3. Проверка: другой разработчик понимает, когда решение пересмотреть и какой критерий покажет, что оно перестало подходить.

## Доступные действия WorldWeaver
При необходимости вызови discover_tools с names: discover_tools,list_skills,read_skill,inspect_object. Это ссылки на существующие команды, а не разрешение на их автоматическое выполнение. После создания читай реальный target, затем применяй зависимые действия отдельным шагом.

## Граница применения
Это справочный Markdown для встроенного агента WorldWeaver. Используй только объявленные в текущем запросе инструменты и их фактические схемы. Навык не добавляет shell, сеть, доступ к секретам, новые разрешения или автоматическое выполнение кода. Если операции нет, дай совет либо подготовь C# для просмотра в поддерживаемом процессе; не выдавай совет за выполненное действие.
