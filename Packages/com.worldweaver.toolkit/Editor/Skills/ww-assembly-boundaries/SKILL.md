# Границы runtime, editor и тестовых сборок без лишней перестройки проекта

## Рабочий подход
1. Проверь существующие asmdef и направления ссылок. Runtime не должен ссылаться на UnityEditor; тесты и editor-код живут в отдельных сборках.
2. Добавляй asmdef ради реальной границы или времени компиляции. Не создавай по сборке на каждый маленький класс и не вноси циклические references.
3. Проверка: Editor и Player собираются отдельно, тестовая сборка обнаруживается Test Runner, необязательный пакет не стал скрытой зависимостью.

## Граница применения
Это справочный Markdown для встроенного агента WorldWeaver. Используй только объявленные в текущем запросе инструменты и их фактические схемы. Навык не добавляет shell, сеть, доступ к секретам, новые разрешения или автоматическое выполнение кода. Если операции нет, дай совет либо подготовь C# для просмотра в поддерживаемом процессе; не выдавай совет за выполненное действие.
