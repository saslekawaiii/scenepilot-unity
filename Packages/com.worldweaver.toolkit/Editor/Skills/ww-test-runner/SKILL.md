# Выбор и запуск EditMode или PlayMode с проверкой фактического результата

## Рабочий подход
1. Проверяй ответственность из исходного запроса. Имена классов и число скриптов из собственного плана не являются требованиями пользователя; уже существующий компонент может выполнять ту же работу.
2. Для новой игровой механики прочитай её реальный исходник и компоненты. Сформулируй наблюдаемые исходное состояние, воздействие и ожидаемый результат. Компиляция, наличие компонента и чтение кода не доказывают поведение.
3. `run_runtime_probe` запускает собственный C# iterator в настоящем Play Mode. Измерь исходные значения, подай реальные виртуальные клавиши/мышь через автоматически очищаемые `probe.Keyboard`/`probe.Mouse` либо публичное UI-событие, пропусти кадры через `yield return null`, сравни фактическое состояние. `probe.Record` сохраняет значения, `probe.Check` — вычисленное условие с наблюдаемыми данными. Используй фактический API из `reflect_api`; не копируй имена из плана как будто они существуют.
4. Проверяй временное и повторное воздействие, обратную связь интерфейса, исходное размещение и столкновения там, где это требует задача. Для циклов ожидания используй время игры и конечный предел. Не считай успешную проверку одной части доказательством остальных частей.
5. Дождись окончательного `job_result`: queued/running/exiting_play не являются успехом. False, исключение, таймаут и отсутствие утверждений означают неуспех. Исправляй реализацию по измеренным причинам и запускай проверку заново.
6. Для имеющихся NUnit-наборов используй `run_tests`. Пустой или пропущенный набор не считается пройденным. Собственные проверки агента дополняют независимую приёмку, а не заменяют её.

## Доступные действия WorldWeaver
При необходимости обнаружь точные схемы `run_runtime_probe`, `run_tests`, `poll_job`, `read_script`, `inspect_component`, `reflect_api`. Runtime C# требует уже включённого разрешения Editor C# и выполняется с полными правами Unity. Не выполняй блокирующий код, файловые/сетевые действия, сохранение сцены или изменение настроек. Проверочные перестановки в Play Mode не реализуют запрос: после выхода сохраняется исходная сцена. Код может только проверять уже созданную реализацию, а затем агент отдельно исправляет её обычными инструментами.

## Граница применения
Это справочный Markdown для встроенного агента WorldWeaver. Используй только объявленные в текущем запросе инструменты и их фактические схемы. Навык не добавляет shell, сеть, доступ к секретам, новые разрешения или автоматическое выполнение кода. Если операции нет, дай совет либо подготовь C# для просмотра в поддерживаемом процессе; не выдавай совет за выполненное действие.
