# Ограничение ресурсов при проверке ScenePilot

После очистки 4 ноября 2026 года используется один QA-редактор одновременно. Допускаются только два постоянных существующих потребителя: `.private/runtime-probe-qa` для программных проверок и `.private/warehouse-consumer-1.8-rc11` для агента и его игровых артефактов. Имена каталогов не означают установленную версию: точный TGZ задаётся manifest и связывается с SHA-256 в протоколе.

Запуск выполняется через `python3 scripts/run_unity_qa.py --project tools|agent --log <новый путь> -- <параметры TestRunner или executeMethod>`. Скрипт не создаёт проекты и не клонирует Library. Он требует 20 ГиБ свободного диска, блокирует второй QA-процесс и останавливает только собственный дочерний Editor при падении свободного места ниже 10 ГиБ или критическом давлении памяти в течение 10 секунд. Нативный пользовательский проект и другие приложения не завершаются. Значения переменных окружения и аргументы чужих процессов не выводятся.

В кандидате RC12 одинаковое содержимое checkpoint сохраняется один раз в `UserSettings/WorldWeaverCheckpoints/shared-content`. Журналы содержат небольшие ссылки на SHA-256. Старые локальные `content` читаются для совместимости. Сохраняются проверки целостности, конфликтов ручной правки и предел 300 МиБ логических данных одной контрольной точки; общий пул ограничен 2 ГиБ. Сборщик удаляет только данные, на которые не ссылается ни один оставшийся журнал. Он не удаляет действующие точки восстановления ради освобождения места.

Скрипт также прекращает собственный процесс после 300 секунд без изменения журнала или отчёта приемки. Предел можно явно настроить в диапазоне 60–3600 секунд; после запроса завершения даётся 15 секунд. Сетевой запрос с обновляющимся отчётом не считается зависшим.

Проверки механизма восстановления входят в [протокол 1.8](validation/1.8.0/README.md). Локальные результаты и ресурсоёмкие потребители исключены из Git. Для новой приёмки используйте существующий потребитель и фиксируйте SHA установленного пакета.
