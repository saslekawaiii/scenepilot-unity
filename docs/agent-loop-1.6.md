# Агент 1.6: наблюдения, ресурсы и проверка всего запроса

Исправления относятся к общему циклу работы. В коде нет выбора плана по словам «Марс» или «девушка»: модель сама выбирает команды, параметры, ресурс и способ исправления. Весовые коэффициенты LLM не менялись.

## Что изменилось

1. `finish_task` доступен и после неудачной попытки завершения. Контроллер больше не удаляет исследование и завершение, требуя произвольного изменения сцены. Результаты `blocked` и `partial` требуют конкретных препятствий и показываются отдельно от выполнения.
2. Неизвестный вызов функции сохраняется в журнале целиком после маскирования секретов. Модель получает точное имя и список объявленных функций. Ничего из отклонённого ответа не выполняется.
3. До восьми независимых синхронных операций чтения могут идти одним ответом. Изменения сцены, загрузки и завершение выполняются отдельно. Маркеры чтения задаёт реестр хоста; модель не может назначить их сама.
4. Индекс всех шагов сохраняется в контексте. `read_task_step` возвращает старые результаты постранично, включая реальные ID и пути, когда они выпали из последних сообщений. Команда не повторяет исходную операцию.
5. В режиме «Глубоко» отдельная проверка охватывает весь запрос после любых изменений. Сравниваются реальные компоненты, размеры, материалы, ссылки, параметры Terrain и исходное состояние для относительных правок. Прежняя неудачная проверка перестаёт считаться текущей после нового изменения. Новая оценка запрашивается через завершение. Дополнительно хост проводит промежуточную оценку после четырёх изменений и останавливает дальнейшее редактирование, когда цель и буквальные критерии уже подтверждены. Относительные команды сравниваются с неизменным исходным состоянием обращения.
6. Одинаковая уже успешная настройка без промежуточного изменения не запускается снова. Агент получает предложение прочитать состояние или запросить свежую проверку. Это ограничивает циклы повторного обновления одного параметра.

Проверка другой модельной генерацией дополняет детерминированные проверки; она не доказывает корректность любого игрового поведения. Для физики, ввода и анимации нужны реальные испытания Play Mode.

## Настоящие модели вместо двух пресетов

`model_search` читает ассеты проекта и метаданные 115 персонажей Microsoft Rocketbox. `model_import` загружает только выбранный FBX и его цветовые текстуры из закреплённой ревизии. Проверяются размер и Git blob SHA-1 каждого файла. URL модель не задаёт. В проект записываются лицензия и `model-source.json`. Повторный импорт кэшированного ресурса не перезаписывает ручные изменения.

`replace_model` работает с существующим актором или объектом: меняет отслеживаемый визуальный дочерний объект, сохраняет корневые компоненты, камеру, идентичность и память NPC. Можно использовать собственный FBX/prefab проекта и подходящий Animator Controller. Prefab с пользовательскими скриптами через эту команду не импортируется.

Для корректного Humanoid без контроллера предусмотрена процедурная поза ходьбы, связанная с фактическим движением. Это анимация костей, а не скачанные клипы. Для Generic-рига нужен совместимый контроллер. Пакет не создаёт фотореалистическую 3D-модель произвольного человека из текста. Rocketbox — библиотека моделей, а не генеративная 3D-модель.

## Контроль состояния Unity

Контрольные точки по-прежнему защищают ручные изменения файлов и сцен. При несовпадении теперь перечисляются конкретные различия; состояние импорта выделяется отдельно. Исправлено самостоятельное перемещение звёздного неба в Edit Mode, которое меняло сериализованную сцену после запечатывания контрольной точки. Следование за камерой выполняется в Play Mode.

Проверка каталога без сети: `python3 scripts/import_model_catalog.py`. Восстановление каталога из закреплённого дерева GitHub: `python3 scripts/import_model_catalog.py --build`. Полные модели не включаются в TGZ; они загружаются по выбору агента.

## Проверки и их границы

`AgentTransferAcceptanceRunner.cs` запускает настоящую модель через публичный `ChatController`: персонаж и замена облика, физический балансир, собственный меш пандуса, чтение библиотеки без изменений, создание и продолжение изменения мира, новый герой с загрузкой ранее не кэшированной модели. Проверяющий код не подставляет планы, не достраивает объекты и не исправляет сцену. Отдельно фиксируются протокольные восстановления: успешное восстановление не приравнивается к окончательному отказу задачи.

`ImportedHumanoidPlayTests.cs` использует сохранённую сцену настоящего агента: реальный клавиатурный ввод, движение контроллера, изменение позы ноги и следование скелета за актором. Подмена геометрии и настройка персонажа в проверке не выполняются.

Промежуточные неудачные отчёты сохраняются с собственными номерами кандидатов. Успешные результаты относятся только к соответствующим архивам и запросам, а не к «любому представимому запросу».

Архив выпуска 1.6.0 побайтно совпадает с последним кандидатом RC7. На нём прошли 713 EditMode-тестов, 26 PlayMode-тестов (два сетевых теста явно пропущены), два отдельных испытания ввода с импортированными персонажами и восемь запросов к настоящей Beam. Для испытаний не оплачивался API: использован существующий временно бесплатный доступ через Ollama. Переносимость этого результата на другую модель и бессрочная бесплатность не подтверждены. Полные хеши и пути приведены в [протоколе выпуска](../deliverables/WorldWeaver-1.6.0-validation.json).
