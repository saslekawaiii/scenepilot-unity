# Чат-ассистент WorldWeaver: актуальный аналог и протокол сравнения

Дата проверки официальных источников: **31.10.2026**. Тема ВКР сохраняется: «Разработка интеллектуального инструментария для автоматизированного создания динамических игровых миров».

Это независимое исследование документации и проект сравнительного испытания. Unity Assistant в рамках этой работы не устанавливался и не испытывался; подписки, пробные периоды и платные API не активировались. Поэтому ниже нет результатов очного соревнования и вывода «WorldWeaver лучше Unity». Ранее выполненные 90 QA-запросов и тесты ядра относятся к зафиксированной версии ВКР, а не доказывают качество нового чат-агента. Локальное дополнение о рабочей реализации 1.2 приведено в разделе 7; внешние возможности и условия Unity ниже сохраняют дату проверки 31.10.2026.

## 1. Что сейчас представляет собой официальный аналог

### Названия и версии

На текущей странице продукта Unity отказывается от общего бренда «Unity AI» и перечисляет инструменты по назначению: in-editor AI assistant, AI gateway, MCP server, официальный plugin и CLI. Muse обозначен как устаревший продукт. Называть современный аналог «Muse» некорректно. [Официальный FAQ](https://unity.com/features/ai).

Проверены целевые страницы, на которые указывают официальные ссылки `@latest`:

| Область | Фактическая документация | Что учитывать при воспроизведении |
|---|---|---|
| In-editor AI assistant | `com.unity.ai.assistant@2.21`, metadata **2.21.0-pre.2**, документация собрана 26.10.2026 | Это предварительная версия; фиксировать реально установленную версию, а не только `latest`. [Assistant](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/index.html) |
| Generators | `com.unity.ai.generators@latest` указывает на 1.7; его manual перенаправляет в Assistant 2.21 | Генераторы представлены в общем руководстве Assistant. | Runtime inference | `com.unity.ai.inference@2.6`, metadata **Sentis 2.6.1** | В версии 2.4 отображаемое имя поменяли **с Inference Engine обратно на Sentis**, без изменения кода. ### Реальные операции чата

В Assistant 2.21 есть **Ask, Plan и Agent**. Ask отвечает и читает проект; Plan составляет план перед выполнением; Agent вызывает инструменты изменения проекта. Уже предусмотрены уровни **Unity Default, Unity Lite, Unity Ultra**. Для Ultra документированы повышенный расход credits и автоматический переход на Default при недоступной мощности. Следовательно, чат, планирование и переключатель «мощности» сами по себе не являются отличием WorldWeaver. [Modes and model tiers](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/manual/about/assistant-modes.html).

Официальные инструменты умеют читать структуру проекта и значения объектов, создавать и удалять GameObjects, добавлять и удалять компоненты, менять настройки объектов и assets. В чате отображаются имя инструмента, аргументы и результат. Это операционный агент, а не только справочник. [Use Assistant tools](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/manual/assets/assistant-tools.html). Unity также описывает написание скриптов, изменение сцены, создание prefabs и проверку изменений с контекстом hierarchy, packages, build settings и console. Это заявленные возможности; фактическую успешность конкретного задания ещё нужно измерить. [Описание Assistant](https://unity.com/blog/unity-ai-assistant-ask-plan-agent-mode-explained).

В 2.21 описан и визуальный контекст: прикрепление изображений, screenshots Editor, автоматический запрос снимка и аннотации. Это ещё одна область, в которой нельзя считать наш текстовый чат заведомо более функциональным. [Images and screenshots](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/manual/automate/image-support.html).

### Генераторы и границы понятия «создать мир»

Текущая документация включает sprites, textures, materials, cubemaps, audio, animations, 3D objects и Terrain Layers. Для 3D Object Generator описан результат prefab с mesh и материалами; рекомендуемая область — простые одночастные предметы, без отдельных подвижных частей, рига и анимации. Генерация 3D-моделей у Unity уже существует. [Create 3D objects](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/manual/3d-terrain/3d-generator-overview.html).

Terrain Layer Generator создаёт совместимые с Terrain материалы и карты Diffuse/Normal/Mask, которые затем назначаются поверхности. Эта страница не описывает генератор поля высот. Из этого нельзя выводить, что универсальный Agent не способен создать или изменить Terrain через код и инструменты: такое задание требует самостоятельной проверки. [Create terrain layers](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/manual/3d-terrain/terrain-overview.html).

Sentis выполняет подготовленные нейронные сети на CPU/GPU целевого устройства; это отдельная runtime-библиотека. Документированы ONNX opset 7–25, а также поддерживаемые модели LiteRT и PyTorch/Core ATen с ограничениями операторов и платформ. Sentis не равнозначен готовому универсальному чат-агенту, но его наличие исключает утверждение «Unity не умеет локальный AI». [Sentis overview](https://docs.unity3d.com/Packages/com.unity.ai.inference@2.6/manual/index.html).

[Legacy MCP server setup](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.21/manual/integration/unity-mcp-get-started.html).

Для бесплатного маршрута WorldWeaver также фиксируются внешние пределы. На 31.10.2026 Classic задаёт один бесплатный ответ за **45 секунд на IP** и **max_tokens=1500**; клиентский интервал начала запросов — **46 секунд**. «Баланс» и «Глубоко» меняют число раундов, отбираемый контекст сцены и ожидание, сохраняя предел одного облачного ответа. Среди HTTP 402 повторяется только распознанный `FREE_LIMIT`, в пределах профиля; обычное требование оплаты и HTTP 400 не повторяются. Подписки и покупки для этого пути не активируются. [Первичный исходник Classic](https://github.com/pollinations/pollinations/blob/73311dad9465c7ddd0ceb9cdc0f2ab8b171f6dbb/text.pollinations.ai/cloudflare-cache/src/origin.js#L24-L27).

Сохранённый `results/pollinations-classic-schema-replay.json` различает совместимость формата и качество агента: A/C в JSON Object Mode дали повреждённый `reply`-префикс, B2 с native schema — HTTP 400 по `propertyNames`, D в обычном текстовом режиме — валидный JSON-экземпляр одной проверки. Поэтому текущий Classic adapter использует текстовый ответ с явным образцом экземпляра и последующую строгую C#-валидацию. Эта проба не доказывает серверное enforced strict-schema и не заменяет полную беседу в Unity. Исторический интервал 31 секунда в QA версии 1.0 сохраняется отдельно и не переносится в актуальный паспорт сравнения.

## 4. Какие преимущества локальной реализации можно фактически проверить

1. **Работа без покупки inference.** Выполнить C1–C9 с уже установленными локальными моделями, нулём платных вызовов и отключёнными внешними provider routes. Это подтверждает отсутствие платы за запросы в данном запуске, а не отсутствие стоимости компьютера, электричества или установки моделей. Бесплатный официальный MCP тоже должен быть отражён в сравнении.
2. **Работа без WAN во время inference.** После прогрева и загрузки моделей выполнить локальный чат, Terrain и NPC с доступным только loopback Ollama. Сохранить endpoint каждого вызова и наблюдение сетевого поведения. Не менять настройки сети пользовательского ПК ради этого исследования; изолированный тест выполняется отдельно при реализации. Ранее успешные localhost-запросы ещё не равны проведённому offline-аудиту.
3. **Управляемая мощность на конкретном M4/16 ГБ.** На фиксированных задачах сравнить фактические модели/digests, quantization, warm/cold p50/p95, время до первого текста, полный tool-cycle и пик памяти. Названия «быстро/умно/максимум» являются presets, пока нет измерений; большую модель нельзя автоматически объявлять лучшей на всех заданиях.
4. **Готовый специализированный процесс.** Измерить время от пустой сцены до работающего мира и NPC, число ручных назначений и исправлений. Сравнивать отдельно «из коробки» и «после разрешённой настройки/генерации кода»; нельзя дать WorldWeaver готовый игровой компонент и запретить аналогу создать свой.
5. **Контракты и воспроизводимость.** На фиксированных spec/seed и ошибочных actions проверить инварианты и отсутствие чужих мутаций. Обосновываемый результат — детерминированная генерация по spec и проверка ограничений, а не детерминированность свободного языка LLM.
6. **Наблюдаемость.** Пользователь может проверить выбранную модель, вызванный инструмент, применённые изменения, исход отказа и состояние мира. У Unity уже есть tool activity; отличия надо показывать на конкретной недостающей диагностике и времени поиска проблемы.

Эти пункты — гипотезы о преимуществе в выбранном процессе. Ни один не доказывает превосходство над всей экосистемой Unity, качество визуального контента или коммерческую готовность.

## 5. Минимальный протокол нового сравнения

- Зафиксировать исходный Git SHA, package versions, Unity patch, ОС, hardware, модель/digest, temperature/context, разрешения, prompt и исходную сцену. Старый тег `experiment-2026-10-30` не перемещать; новый интерфейс и результаты имеют отдельный commit и набор протоколов.
- Для каждой сравнимой операции выполнить минимум пять независимых запусков из одинакового состояния; один и тот же предел попыток/исправлений, одинаковые входные файлы и бюджет времени. Пять запусков дают описательный результат для этих условий, не общую статистику надёжности.
- Сохранить все исходы: успех с первой попытки, успех после исправления, частичный результат, отказ, timeout, недоступность сервиса. Человеческую доводку и время ожидания подтверждения считать отдельно.
- Проверять scene/components/assets через независимый manifest, compile/Play Mode и изображения. Ответ «готово» без нужного объекта, рабочего компонента или действия — не успех.
- Разделить программные инварианты, полноту задания, полезность текста и визуальную оценку. Для красоты заранее определить рубрику и по возможности независимых оценщиков; не сводить субъективность к проценту прохождения unit-тестов.
- Метрики: завершение задания, число ручных действий/повторов, полное время до проверенного результата, расход внешнего inference, корректность Undo/Cancel, объём незапрошенных изменений. Latency модели не подменяет полное время создания мира.
- Пока нет разрешённого доступного Unity Assistant, его столбец результата — **«не измерено, документировано»**. Для локальных прогонов WorldWeaver можно получить реальные результаты без покупки API; это не превращает документационный столбец аналога в проигрыш.

## 6. Практический вывод для разработки

Новый WorldWeaver должен показывать свободный диалог и фактически исполняемые операции в одном потоке: запрос → план/инструмент → изменение Unity → проверяемый результат. Переключение модели и мощности, история беседы и Stop нужны для удобства, но уже присутствуют у развитого аналога в близкой форме. Сильная проверяемая специализация — воспроизводимый Terrain и готовые NPC с индивидуальными знаниями, ограничениями действий и видимым состоянием, доступные через единый чат и локальный inference. Общую работу со scripts, 3D assets и всем Editor нельзя объявлять решённой только из-за успешной генерации одной долины.

Исследование не изменяет существующие главы диплома, код и опубликованные эксперименты. Его выводы служат требованиями к следующей реализации и отдельному честному испытанию.

Исходные формулировки заданий C1–C12 выше сохраняются как протокол; наличие инструмента в коде не считается прохождением этих заданий.
