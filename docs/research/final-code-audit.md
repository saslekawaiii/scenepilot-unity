Номера строк относятся к версии на момент аудита; последующие исправления основного разработчика могут их изменить.

## Найденные проблемы

### A1 — P1: создание demo меняет существующую поставку проекта и перезаписывает сцену

**Место:** `Packages/com.worldweaver.toolkit/Editor/DemoBuilder.cs:49` и `:50`, метод `Create`.

Команда называется Create Demo in New Scene, однако сохраняет новую сцену всегда в `Assets/WorldWeaverDemo/WorldWeaverDemo.unity`. Повторный вызов перезаписывает уже доработанную пользователем demo. Перед этим запрос сохранения текущих изменений может предложить сохранить именно эту сцену, после чего сохранённый результат будет заменён новой генерацией. Кроме того, присваивание `EditorBuildSettings.scenes = new[] { demo }` молча заменяет весь прежний список сцен сборки.

**Воспроизведение:** в проекте с двумя настроенными build scenes создать demo, изменить в ней объект, сохранить и вызвать команду повторно. Проверить сохранённую сцену и список сцен сборки. Ожидается сохранность пользовательской версии и предыдущих build scenes; текущая реализация заменяет их.

**Минимальное исправление:** выбирать уникальный путь сцены, как уже делается для ассетов; не менять build settings или добавлять сцену без удаления существующих записей. Это исправление сохранности проекта, а не новая функция. В README после исправления должен быть описан фактический путь созданной сцены.

### A2 — P1: запуск реального сценария не защищает несохранённую сцену

**Место:** `Packages/com.worldweaver.toolkit/Editor/RealScenario.cs:21`, метод `Begin`.

Если demo уже существует, helper напрямую вызывает `EditorSceneManager.OpenScene` с режимом Single. В отличие от `DemoBuilder.Create`, перед этим нет `SaveCurrentModifiedScenesIfUserWantsTo`. Открытие другой сцены программным API не должно использоваться как замена явному запросу сохранения.

**Воспроизведение:** открыть другую рабочую сцену, изменить объект без сохранения и вызвать Tools → WorldWeaver → Run Real Local Scenario либо Run Real Free Cloud Scenario. Проверять следует на копии сцены. Требуемое поведение — предложение сохранить/отменить переход до открытия demo; текущий код такую проверку не выполняет.

**Минимальное исправление:** добавить ту же защиту сохранения для интерактивного режима и завершать метод при отмене. Batch-runner можно оставить без UI-запроса, поскольку он запускается в специально выделенном проекте.

### A3 — P2: отмена индексации памяти после commit выглядит как отмена всего действия

**Место:** `Packages/com.worldweaver.toolkit/Runtime/Dialogue/NpcPipeline.cs:80`, `:86`, `:93`; `Runtime/NPC/IntelligentNPC.cs:69`–`:75`; `Runtime/Dialogue/DemoDialogue.cs:53`–`:56`.

Dispatcher сначала реально изменяет Inventory или начинает движение. Затем pipeline асинхронно индексирует разговор и эпизод. `ProviderException` памяти учитывается как дополнительная ошибка, но `OperationCanceledException` выходит наружу. Поэтому отмена во время второго embedding-запроса может дать `LastError="Cancelled."` и оставить прежнюю `LastSpeech`, хотя предмет уже передан. Trace содержит принятое решение, однако пользовательский результат выглядит как неисполненный запрос. Повторная отправка после такой индикации может привести ко второму отдельному действию, если модель вновь его выберет.

**Воспроизведение:** использовать тестовый IEmbeddingProvider, который успешно индексирует знания и query, а при `RememberAsync` ждёт отмены. Вернуть реальный для dispatcher валидный GiveItem(1), отменить token во время запоминания. Проверить, что Inventory уже 9/1, но внешний Task завершён отменой и `IntelligentNPC.LastSpeech` не обновлена.

**Минимальное исправление:** различать отмену до commit и после commit. После commit сохранять и возвращать статус выполненного действия, а неудачу памяти отмечать отдельно. Произвольный rollback внешних действий здесь не требуется и не должен обещаться.

### A4 — P2: незаполненный профиль ломает отрисовку MODELS

**Место:** `Packages/com.worldweaver.toolkit/Editor/WorldWeaverWindow.cs:169`; `Runtime/Orchestration/OrchestratorProfile.cs:14`.

Во время `OnGUI` окно без защиты вызывает `routes.Resolve(task)`. Для нового Orchestrator Profile хотя бы один маршрут обычно ещё не назначен; `Resolve` бросает `InvalidOperationException`. Исключение возникает при отрисовке, до нажатия Health check, и обходится без общего обработчика `Run`. Это штатный этап настройки, а не ошибка внешнего API.

**Воспроизведение:** создать Assets → Create → WorldWeaver → Orchestrator Profile с пустыми полями и выбрать его на вкладке MODELS. Ожидается сообщение о недостающем маршруте и возможность продолжить настройку без исключений в Console.

**Минимальное исправление:** проверять назначенность соответствующей ссылки в UI, отображать missing route и отключать только её Health check. Исключение `Resolve` уместно оставить для вызова runtime без корректной конфигурации.

### A5 — P2: повторная генерация оставляет раскраску от прежнего рельефа

**Место:** `Packages/com.worldweaver.toolkit/Editor/TerrainAuthoring.cs:31`–`:38` и `:52`–`:57`.

При Create alphamap вычисляется из высот и устанавливается через `SetAlphamaps`. При Regenerate обновляются высоты, размер и вода, но alphamap не пересчитывается. Поэтому при заметной смене seed, valleyDepth или mountainStrength снег/скалы могут остаться на местах старых высот. Геометрия воспроизводима, однако визуальная раскраска больше не соответствует текущей спецификации.

**Воспроизведение:** создать Terrain с выраженными горами, затем Regenerate с тем же размером, но другим seed и `mountainStrength=0`. Сопоставить снег/скалы и нормированную высоту. Дополнительно сравнить результат Create с новой спецификацией и Regenerate до неё: при одинаковых высотах раскраска будет различаться.

**Минимальное исправление:** вынести расчёт alphamap в общий метод и вызывать после установки новых высот. Если это откладывается, явно указать ограничение повторной генерации в документации; не обещать полную визуальную эквивалентность Create и Regenerate.

## Что не считается обнаруженным дефектом

- 29/30 совпадений факта облачной модели и 16/30 доставленных ответов не противоречат друг другу: parser/dispatcher могут отклонить пакет действий. README эту разницу раскрывает.
- `actions=[]` либо Wait при автономном выборе допустимы. Они не подтверждают ожидаемое перемещение и должны учитываться как ограничение конкретной демонстрационной задачи.
- Free Cloud переключает диалог, а planning остаётся локальным; это соответствует README и маршрутам `DemoBuilder`.
- QA использует Qwen3.5 2B, интерактивная demo — Qwen2.5-Coder 7.6B. `ResearchRunner.cs:36`–`:39` явно закрепляет различие; нельзя смешивать QA-числа с новой моделью demo.
- Предварительная валидация встроенных действий синхронна; отклонённый пакет не исполняется частично. Гарантии произвольного пользовательского IGameAction ограничены договором Validate без побочного эффекта, и это раскрыто в ТЗ.
