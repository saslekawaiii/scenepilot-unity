# WorldWeaver 1.1: историческое руководство единого чата

> Это руководство описывает версию 1.1 и её результаты. Для версии 1.2 используйте [действующее руководство пакета](../../Packages/com.worldweaver.toolkit/Documentation~/index.md) и [границы агента](../agent-architecture-and-limits.md). Старые показатели ниже сохранены без переатрибуции.

Руководство отражает код на 31.10.2026, редакция `60192a9`. В нём реализованы чат в Unity Editor, выбор модели и режима работы, создание окружения и NPC, изменение существующей сцены и подготовка C# с просмотром перед импортом. Один полный локальный разговор на предшествующей редакции `0aa9bdf` прошёл 7/7 усиленных критериев; его просмотренный C# отдельно прошёл импорт, компиляцию, подключение и откат. Эти результаты относятся к указанным входам и версиям, а не гарантируют любой следующий запрос.

Цель доработки — удобный локальный помощник для создания игровых миров. Превосходство над Unity Assistant является целью сравнения, а не установленным результатом.

## Начало работы

1. Откройте проект в Unity 6.3 и нужную сцену. Для первого знакомства удобно создать пустую сцену обычной командой Unity. Чат работает с текущей сценой.
2. Запустите Ollama. Для помощника нужна установленная текстовая модель, начальное назначение — Qwen3.5 9B (`qwen3.5:9b`); для диалогов NPC с поиском знаний — EmbeddingGemma.
3. Откройте **Tools → WorldWeaver → Чат**. Слева находится история, сверху — модель и режим, снизу — поле сообщения.
4. Нажмите **Обновить**, затем выберите доступную локальную модель в поле **Модель помощника**. Начальный вариант — `qwen3.5:9b`, режим **Баланс**. На машине с 16 ГБ эта модель занимает значительную часть памяти, а выполнение нескольких раундов проверки может занимать несколько минут. Состояние подключения отображается рядом.
5. Напишите запрос обычными словами. **Enter** отправляет сообщение, **Shift+Enter** добавляет строку. Кнопки «Создать мир», «Добавить персонажа», «Изменить сцену» и «Написать скрипт» помогают начать запрос, но не обязательны.

Если модели ещё не установлены, команды Ollama для этого пути:

```sh
ollama pull qwen3.5:9b
ollama pull embeddinggemma
```

Список моделей получает доступные текстовые модели из локальной Ollama. Установленные Qwen3.5 2B и Qwen2.5-Coder также можно выбрать; архивные QA- и runtime-протоколы сохраняют свои прежние модели. Также предусмотрен бесплатный облачный маршрут Pollinations Classic; его доступность и квоты зависят от внешнего сервиса. На 31.10.2026 бесплатный предел — один ответ за **45 секунд на IP**, клиент выдерживает **46 секунд** между началами запросов. Отдельный облачный ответ ограничен `max_tokens=1500`. Ожидание очереди входит в общий бюджет операции. Среди HTTP 402 ограниченно повторяется только код `FREE_LIMIT`; обычное требование оплаты и HTTP 400 не повторяются, покупки не выполняются. [Пределы Classic в первичном исходнике](https://github.com/pollinations/pollinations/blob/73311dad9465c7ddd0ceb9cdc0f2ab8b171f6dbb/text.pollinations.ai/cloudflare-cache/src/origin.js#L24-L27).

Проверка каталога при открытии/обновлении окна обращается и к облачному каталогу. Поэтому выбор локальной модели означает локальное выполнение её запросов, но сам по себе ещё не доказывает полное отсутствие сетевой активности окна. Текущий Classic запрашивает JSON-экземпляр обычным текстовым ответом, затем проверяет его в C#; гарантированное соблюдение всей схемы на стороне сервера не заявляется. Диагностический протокол `results/pollinations-classic-schema-replay.json` сохраняет отказы JSON-mode/native schema и один валидный текстовый вариант.

## Модель, режим и применение изменений

| Настройка | Что меняется |
|---|---|
| **Модель помощника** | Какая модель обрабатывает сообщения этого чата. У уже созданных игровых NPC сохраняются собственные назначенные профили моделей. |
| **Быстро** | Короткий запрос и один проход. Подходит для небольшого задания или объяснения. |
| **Баланс** | До трёх проходов для выполнения и исправления плана. |
| **Глубоко** | До шести проходов, больший контекст сцены и бюджет ожидания для сложного задания; локальный лимит ответа также расширяется. Выбранная модель остаётся той же. |
| **Применять изменения автоматически** | Обычные изменения сцены выполняются после проверки плана. Если выключить переключатель, предложенные изменения ждут кнопки **Применить план**. |

Новый C# и подключение созданного скрипта всегда остаются планом для просмотра, независимо от автоматического применения обычных изменений сцены.

Для бесплатного облака во всех трёх режимах действует предел 1500 токенов на один ответ. Выбор «Глубоко» может дать больше раундов проверки и контекста, но не снимает этот предел и не гарантирует помещение большого C#-скрипта в один ответ.

Во время запроса рядом с текущим этапом обновляется прошедшее время. Это длительность ожидания, а не прогноз завершения. Кнопка отправки превращается в **Остановить**; также работает **Escape**. Остановка прекращает дальнейшее выполнение. Уже завершённые изменения остаются в сцене и перечисляются в результатах действий. Кнопка **Отменить действие** вызывает стандартный Undo Unity для последнего действия, включая ручное.

Для восстановления импортированного C# используется отдельная кнопка **Вернуть предыдущий код** у того сообщения, через которое применялся исходник. Она появляется, когда для этого импорта ещё доступна сохранённая предыдущая версия, и недоступна во время запроса, Play Mode и компиляции. После её нажатия восстанавливаются прежние файлы; новый файл, которого до импорта не было, удаляется. Unity повторно проверяет компиляцию. Если вы изменили импортированный исходник вручную, автоматическое восстановление откажется перезаписывать ваши правки. Для долговременной истории версий проекта используйте Git.

## Первый мир и продолжение разговора

Отправляйте запросы по очереди в одном чате:

> Создай лесную долину размером 160 на 160 метров: ровно 12 деревьев, 3 дома и 4 камня. Добавь подходящие свет и камеру для осмотра мира.

После ответа раскройте **Результаты действий** и осмотрите сцену. Окружение создаётся настоящими объектами Unity: Terrain с высотами и слоями поверхности, водой, домами, деревьями, камнями, источником света и камерой. Дома, деревья и персонажи используют встроенную геометрию WorldWeaver. Это готовые процедурные формы; генерация новой художественной 3D-модели по референсу в этом процессе не реализована.

Следующее сообщение:

> Уменьши height существующего рельефа до 24 метров. Сохрани деревья, дома и камни; второй мир не создавай.

Операция обновления мира пересоздаёт данные рельефа, материалы поверхности и воду, а существующие объекты окружения привязывает к новой высоте. Результат нужно проверять по выбранному Terrain и его фактическим размерам. Ответ модели «готово» без нужного изменения сцены не считается приёмкой.

Другие доступные запросы:

> Добавь три оранжевых точечных источника света Point около площади. Существующее солнце сохрани.

> Создай деревянный ящик рядом с домом, затем сделай его темнее.

> Создай дополнительную камеру с видом на площадь.

Предусмотрены размещение объектов, изменение Transform, цвета/материала, Directional/Point/Spot-света и параметров камеры. Новые Point/Spot по умолчанию поднимаются минимум на 3 м над Terrain и сгенерированной водой в той же точке x/z. Это начальное размещение, поэтому после изменения высот рельефа свет нужно проверить повторно. Существующий свет перемещается с такой коррекцией только при явно заданном on_terrain=true; on_terrain=false сохраняет точные координаты. Дальность света должна достигать земли с его конечной высоты. Размещённый объект можно указать по имени или выделить в Unity, нажать **+ → Прикрепить контекст выделения** и описать правку. Прикрепление передаёт сведения о выделении; загрузка изображений через этот пункт не реализована.

Чтобы обсудить идею, достаточно обычного вопроса: «Объясни, что находится в сцене» или «Предложи план, пока ничего не меняй». При выключенном автоматическом применении предложенные изменения останутся ожидающим планом.

Для явного объяснения без изменений используйте: «Только объясни в чате. Ничего не создавай и не изменяй». Распознанная такая просьба допускает только чтение контекста; прежний ожидающий код сохраняется. Проверка явных формулировок ограничена и не заменяет просмотр результата при свободном или смешанном запросе.

## Создание персонажа и проверка его знаний

Продолжите в том же чате:

> Создай в этой долине NPC по имени Игнат: роль — страж, личность — осторожный. Добавь ему знание: «Северные ворота открываются в шесть утра».

> Теперь измени его цель: патрулировать площадь и северные ворота. Остальные сведения о страже сохрани.

Создание персонажа подключает `IntelligentNPC`, инвентарь, игровую сущность, базу знаний с областью этого NPC и профили моделей. Изменение цели редактирует данные существующего персонажа. В Inspector можно проверить его имя, роль, личность, цель и назначенную базу знаний.

Для знакомства с runtime-диалогом включите **Play Mode** и откройте **Game**. При создании NPC добавляется панель **Диалог с персонажем**: выберите Игната и спросите, когда открываются северные ворота. Панель вызывает настоящий NPC pipeline; речь, отказ или ошибка сервиса отображаются по полученному результату. Во время Play Mode редакторский чат не выполняет изменения проекта.

Текстовая цель «патрулировать» и фактическое движение проверяются отдельно. Для движения `IntelligentNPC` через NavMesh нужны настроенные `NavMeshAgent` и подходящая NavMesh; создание нового NPC этим инструментом само по себе их не подготавливает. Для простого движения по заданным точкам также предусмотрен отдельный встроенный компонент поведения. В локальном разговоре проверены изменение цели и настройки patrol; фактическая навигация между семантическими площадью и воротами им не измерялась.

## Скрипт с просмотром перед импортом

1. Попросите: «Напиши отдельный C# MonoBehaviour для плавного вращения объекта вокруг оси Y со скоростью 30 градусов в секунду. Подготовь код для моего ревью, пока не импортируй его».
2. В ответе раскройте **Код · ИмяСкрипта.cs**. Код можно прочитать и скопировать. В этот момент это ожидающий план; новый вариант ещё не импортирован, а существующий файл при его наличии остаётся прежним.
3. После просмотра нажмите **Применить план**, если хотите импортировать этот вариант. Unity запустит настоящую компиляцию; результат появится в чате.
4. При ошибке попросите исправление. После успешной компиляции отдельным запросом укажите, к какому объекту подключить скрипт; эта операция также проходит через **Применить план**.
5. Чтобы восстановить файлы до этого импорта, найдите соответствующее сообщение и нажмите **Вернуть предыдущий код**. Проверьте сообщение о восстановлении и дождитесь повторной компиляции Unity; эта кнопка привязана к конкретному импорту, а не ко всем прежним сообщениям с кодом.

После успешного импорта и после восстановления блок кода остаётся в соответствующем сообщении для чтения и копирования. Исторический блок сам по себе не является ожидающим планом и не даёт повторной кнопки применения. Новый вариант кода нужно подготовить новым сообщением и просмотреть отдельно.

Для готового простого поведения можно попросить вращение, покачивание, движение по точкам или следование за явно указанным объектом. В таком случае помощник может использовать встроенный компонент вместо написания нового C#. Если нужен именно исходный код, укажите это в запросе.

## История, сохранение и пределы текущей версии

- **Новый чат** начинает отдельный разговор; прежние сообщения доступны в истории слева. История сохраняется локально для проекта, включая ожидающие планы. В модель передаётся ограниченная часть последних сообщений и снимок сцены, поэтому длинный разговор не означает неограниченную память модели.
- Сохранить сцену можно обычной командой Unity либо явным запросом помощнику. Его инструмент сохранения создаёт отдельный файл в области WorldWeaver с уникальным именем. Он не сохраняет сцену автоматически после каждого сообщения.
- Отмена создания объекта может оставить созданные файлы ассетов в Project. Восстановление проверенных C# имеет отдельный механизм и сохраняет последующие ручные правки, отказываясь их перезаписывать.
- Поддерживаемые инструменты ограничены текущей сценой и описанными операциями. Генерация произвольной игры, художественная оценка, автоматический rigging, импорт любого Asset Store-пакета и универсальное управление всеми настройками Unity не подтверждены этой реализацией.

## Короткое сравнение с текущим Unity Assistant

**Статусы WorldWeaver ниже означают наличие реализации; область фактически выполненной приёмки указана отдельно.** Unity изучен по официальной документации Assistant 2.21.0-pre.2; очный прогон аналога не выполнялся. Слово «не установлено» означает отсутствие подтверждения готового процесса в просмотренных источниках, а не техническую невозможность.

## Как подтверждены результаты

Для нового чата подготовлен отдельный приёмочный runner: **Tools → WorldWeaver → Testing → Chat Acceptance**. Это явная тестовая команда: она создаёт пустую тестовую сцену, в графическом редакторе сначала предлагает сохранить текущую сцену, затем выполняет семь запросов одной настоящей локальной модели в одном разговоре. Скриптовый план остаётся ожидающим ревью и не применяется тестом.

Завершённый [local9b-v2, 7/7](../../results/chat-agent-acceptance-local9b-v2.json) относится к qwen3.5:9b, режиму «Баланс» и редакции `0aa9bdf`. Проверены фактические Terrain, количества объектов, сохранение существующего мира, знания и цель NPC, три оранжевых Point над поверхностью/водой с достаточным range, отсутствие импорта C# без ревью и отсутствие изменений при объяснении сцены. Для каждого запроса записаны ответ, шаги, состояние до/после, время и причины неуспеха.
