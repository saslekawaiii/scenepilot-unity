# Общий рабочий процесс агента, 1.4.0

Причина отказа на запрос с картой высот, кратерами, пещерами и жителями была в маршрутизации инструментов: слово «жители» выбирало команды NPC, а Terrain не попадал в сокращённую схему. Модель видела справку по ландшафту, но не получала команды для его изменения. Пустой ответ `complete:true` завершался надписью «Готово».

Исправление развивает общие возможности агента, а не заменяет этот запрос готовым сценарием. Модель продолжает сама выбирать действия. В коде нет таблицы «запрос → готовая сцена» и нет исполнения заранее записанного плана из приёмочного теста.

## Как агент выбирает действия

- `discover_tools` открывает фактические определения команд по категории или имени. Категории: Terrain, геометрия и иерархия, персонажи, NPC, материалы, физика, интерфейс, выживание, код, навигация, представление и проект. Сокращённая схема текущего шага не считается полным списком возможностей.
- `list_skills` и `read_skill` позволяют найти и загрузить нужный рецепт во время задачи. В каждом из 80 навыков указаны связанные реальные команды. Чтение навыка открывает их определения следующему шагу; Markdown не исполняется как программа и не расширяет разрешения.
- `plan_task` сохраняет до 12 этапов составной задачи. В интерфейсе они обозначены как план, без вымышленных галочек выполнения.
- После действия агент получает фактические цели, компоненты, ошибки и результаты проверок. Созданные объекты повторно не создаются; зависимые операции выполняются после получения реального target.
- Сложные конструктивные запросы имеют больше шагов и общий бюджет времени. Мощность модели продолжает управлять параметрами отдельного обращения. Ограничение бесплатного внешнего API и скорость локальной модели всё равно влияют на время.

## Новые составные команды

| Команда | Фактическая возможность |
| --- | --- |
| `create_node`, `set_parent` | Пустые узлы, компонование иерархии, защита от циклов |
| `create_mesh` | Собственные вершины, треугольники, UV, сохранённый Mesh и MeshCollider |
| `shape_terrain` | Локальная чаша кратера с ободом, холм, выравнивание, воспроизводимая лунная поверхность |
| `create_cave` | Отверстие Terrain, спуск, пол, стены, свод и физический коллайдер |
| `configure_physics` | Rigidbody, коллайдер, масса, гравитация, трение и отскок |
| `create_ui_element` | Canvas, панель, текст, кнопка, слайдер и EventSystem; кнопка может переключать явно указанный объект |
| `configure_audio` | Настройка существующего AudioClip и AudioSource |
| `configure_animator` | Привязка существующего AnimatorController |
| `configure_survival`, `create_resource` | Кислород, HP, воздействие среды, база восстановления, конечные запасы и сбор образцов |
| `verify_scene` | Независимые проверки компонентов, активности, меша/коллайдера, высоты и настоящего пути NavMesh |

Команды дополняют существующие инструменты мира, NPC, импорта материалов, анимированного героя, редактирования компонентов, компиляции и тестов. Если готовая команда не реализует механику, агент должен подготовить небольшой полный C# компонент через существующий процесс просмотра, компиляции и подключения. Новый код не объявляется рабочим до настоящего результата компиляции и проверки поведения.

## Навыки и происхождение

Каталог вырос с 60 до 80: добавлены прикладные рецепты композиции, геометрии, Terrain, физики, UI, звука, анимации, взаимодействий, выживания, поиска возможностей, планирования, восстановления и проверок. Обновлены ссылки на команды у существующих навыков. Все файлы воспроизводимо собираются `scripts/import_agent_skills.py --build`; SHA-256 и исходные MIT-лицензии сохраняются.

Это адаптации зафиксированных источников [Besty0728/Unity-Skills](https://github.com/Besty0728/Unity-Skills/tree/fb7a8d4208671bca1d1013b2776eb2e4917f4964) и [Nice-Wolf-Studio/unity-claude-skills](https://github.com/Nice-Wolf-Studio/unity-claude-skills/tree/a149d3e995420432f52b0899092daa4b069f441f). Новые рецепты написаны под команды WorldWeaver; чужие REST-клиенты и режимы bypass не переносились.

## Граница достоверности

Система не гарантирует выполнение любого вообразимого запроса. Она ограничена возможностями модели, доступными ассетами, API Unity, временем, памятью и реализованными инструментами. Нельзя получить произвольную профессиональную модель с ригом, художественную анимацию или полноценную игру только добавлением Markdown.

Проверка «изменения применены» означает наличие настоящего действия текущей задачи, а не выполнение всех смысловых требований. Такая карточка остаётся нейтральной. `verify_scene` подтверждает только перечисленные условия; наличие компонента не доказывает прохождение игры. Проверки поведения, визуального качества и реального ввода учитываются отдельно. Пустой отказ при запросе изменений больше не считается успехом.

Лунная поверхность процедурная, не измеренная география NASA. Для настоящих пещер используются [отверстия TerrainData](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/terraindata/setholes) и отдельная геометрия. Значение лунной гравитации 1,62 м/с² соответствует [справке NASA](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/moon/); кислородная система является игровой моделью, а не симуляцией жизнеобеспечения.

## Проверка без подмены модели

`scripts/GeneralAgentAcceptanceRunner.cs` содержит разные обычные запросы: собственный мост, физический мяч, рабочее меню, рельеф с пещерой, новая C# механика и поиск возможностей в режиме объяснения. Он использует настоящий `ChatController` и настоящий выбранный провайдер. Планы инструментов не подставляются, неудачный ответ не заменяется ручным построением сцены. Полные исходные ответы и журнал шагов сохраняются вместе с инвентарём хешей проверяемого пакета.

Результаты отдельных прогонов публикуются отдельно; наличие корпуса не является утверждением, что все его запросы прошли.
