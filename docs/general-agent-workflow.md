# Общий рабочий процесс агента, 1.4.0

Причина отказа на запрос с картой высот, кратерами, пещерами и жителями была в маршрутизации инструментов: слово «жители» выбирало команды NPC, а Terrain не попадал в сокращённую схему. Модель видела справку по ландшафту, но не получала команды для его изменения. Пустой ответ `complete:true` завершался надписью «Готово».

Исправление развивает общие возможности агента, а не заменяет этот запрос готовым сценарием. Модель продолжает сама выбирать действия. В коде нет таблицы «запрос → готовая сцена» и нет исполнения заранее записанного плана из приёмочного теста.

## Как агент выбирает действия

- `discover_tools` открывает фактические определения команд по категории или имени. Категории: Terrain, геометрия и иерархия, персонажи, NPC, материалы, физика, интерфейс, выживание, код, навигация, представление и проект. Сокращённая схема текущего шага не считается полным списком возможностей.
- `list_skills` и `read_skill` позволяют найти и загрузить нужный рецепт во время задачи. В каждом из 80 навыков указаны связанные реальные команды. Чтение навыка открывает их определения следующему шагу; Markdown не исполняется как программа и не расширяет разрешения.
- `plan_task` сохраняет до 12 этапов составной задачи. В интерфейсе они обозначены как план, без вымышленных галочек выполнения.
- После действия агент получает фактические цели, компоненты, размеры меша/UI, массу, отскок, состояние привязки кнопки, ошибки и результаты проверок. Созданные объекты повторно не создаются; зависимые операции выполняются после получения реального target.
- Сложные конструктивные запросы имеют больше шагов и общий бюджет времени. Мощность модели продолжает управлять параметрами отдельного обращения. Ограничение бесплатного внешнего API и скорость локальной модели всё равно влияют на время.

## Новые составные команды

| Команда | Фактическая возможность |
| --- | --- |
| `create_node`, `set_parent` | Пустые узлы, компонование иерархии, защита от циклов; единые уникальные имена по умолчанию |
| `create_mesh` | Собственные вершины, треугольники, UV, сохранённый Mesh и MeshCollider |
| `shape_terrain` | Чаша кратера с ободом (глубина по модулю), холм, выравнивание, процедурная лунная поверхность; повышение разрешения с сохранением рельефа и отверстий |
| `create_cave` | Отверстие Terrain, спуск, пол, стены, свод и физический коллайдер |
| `configure_physics` | Rigidbody, коллайдер, масса, гравитация, трение и отскок |
| `create_ui_element`, `configure_ui` | Canvas, панель, текст, кнопка, слайдер и EventSystem; привязка уже созданной кнопки к переключаемому объекту, правка размеров/текста/видимости в пикселях Canvas |
| `configure_audio` | Настройка существующего AudioClip и AudioSource |
| `configure_animator` | Привязка существующего AnimatorController |
| `configure_survival`, `create_resource` | Кислород, HP, воздействие среды, база восстановления, конечные запасы и сбор образцов |
| `verify_scene` | Независимые проверки компонентов, активности, меша/коллайдера, высоты и настоящего пути NavMesh |

Команды дополняют существующие инструменты мира, NPC, импорта материалов, анимированного героя, редактирования компонентов, компиляции и тестов. Если готовая команда не реализует механику, агент должен подготовить небольшой полный C# компонент через существующий процесс просмотра, компиляции и подключения. Новый код не объявляется рабочим до настоящего результата компиляции и проверки поведения. Если отдельно запрошен пустой узел для компонента, он подготавливается до черновика; скрытый примитив не считается пустым узлом. Три одинаковые ошибки проверки плана останавливают бесполезное повторение.

## Навыки и происхождение

Каталог вырос с 60 до 80: добавлены прикладные рецепты композиции, геометрии, Terrain, физики, UI, звука, анимации, взаимодействий, выживания, поиска возможностей, планирования, восстановления и проверок. Обновлены ссылки на команды у существующих навыков. Все файлы воспроизводимо собираются `scripts/import_agent_skills.py --build`; SHA-256 и исходные MIT-лицензии сохраняются.

Это адаптации зафиксированных источников [Besty0728/Unity-Skills](https://github.com/Besty0728/Unity-Skills/tree/fb7a8d4208671bca1d1013b2776eb2e4917f4964) и [Nice-Wolf-Studio/unity-claude-skills](https://github.com/Nice-Wolf-Studio/unity-claude-skills/tree/a149d3e995420432f52b0899092daa4b069f441f). ## Расширение без правок ядра

В окне чата откройте «Навыки», затем дополнительные настройки и поле «Дополнительные папки с навыками · по одной на строку». В указанной папке каждый навык лежит в `skill-id/SKILL.md`. Например:

```markdown
---
name: project-interaction
description: Создание взаимодействующих объектов нашего проекта.
category: gameplay
keywords: взаимодействие дверь рычаг interact door lever
tools: create_node,inspect_component,draft_script,verify_scene
license: MIT
mode: advisory
---

# Взаимодействия проекта
Сначала найди существующие компоненты и соглашения проекта.
Повторно используй подходящую механику. Для новой механики подготовь
полный C# компонент, опиши его поля и подключение. После компиляции
проверь фактическое поведение и сообщи, что осталось непроверенным.
```

Уникальное имя должно совпадать с именем папки. Метаданные записываются простыми однострочными значениями; тело — обычный Markdown. Агент ищет описания через `list_skills` и читает полное тело через `read_skill`. Поле `tools` позволяет открыть реальные определения уже зарегистрированных команд на следующем шаге. Произвольное название команды не создаёт новый инструмент. Для новой операции Unity нужен адаптер с проверкой параметров или C# компонент через процесс просмотра и компиляции.

В конструктивном цикле модель выбирает одно действие за шаг. После успеха ей передаются реальные объекты и результаты, без повторного подсовывания старого ответа как примера. Идентичное создание без имени повторно не исполняется в том же обращении; для намеренных одинаковых копий нужны разные имена. Текстовые облачные адаптеры получают полный актуальный контракт параметров, даже если API не поддерживает структурированный вывод. Все эти правила общие для инструментов и не содержат готового плана конкретной сцены.

## Граница достоверности

Система не гарантирует выполнение любого вообразимого запроса. Она ограничена возможностями модели, доступными ассетами, API Unity, временем, памятью и реализованными инструментами. Нельзя получить произвольную профессиональную модель с ригом, художественную анимацию или полноценную игру только добавлением Markdown.

Проверка «изменения применены» означает наличие настоящего действия текущей задачи, а не выполнение всех смысловых требований. Такая карточка остаётся нейтральной. `verify_scene` подтверждает только перечисленные условия; наличие компонента не доказывает прохождение игры. Проверки поведения, визуального качества и реального ввода учитываются отдельно. Пустой отказ при запросе изменений больше не считается успехом.

Лунная поверхность процедурная, не измеренная география NASA. Для настоящих пещер используются [отверстия TerrainData](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/terraindata/setholes) и отдельная геометрия. Значение лунной гравитации 1,62 м/с² соответствует [справке NASA](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/moon/); кислородная система является игровой моделью, а не симуляцией жизнеобеспечения.

## Проверка без подмены модели

`scripts/GeneralAgentAcceptanceRunner.cs` содержит разные обычные запросы: собственный мост, физический мяч, рабочее меню, рельеф с пещерой, новая C# механика и поиск возможностей в режиме объяснения. Он использует настоящий `ChatController` и настоящий выбранный провайдер. Для загрузки навыка учитывается как настоящий read_skill, так и фактически переданный проверенный Markdown из автоматического выбора; способ сохраняется отдельно. Планы инструментов не подставляются, неудачный ответ не заменяется ручным построением сцены. Полные исходные ответы и журнал шагов сохраняются вместе с инвентарём хешей проверяемого пакета.

Результаты отдельных прогонов публикуются отдельно; наличие корпуса не является утверждением, что все его запросы прошли.

В окончательном корпусе глубина кратера проверяется прямым замером поверхности до и после действия. У прежних протоколов была неверная база после перестройки лунного профиля; исходные файлы сохранены вместе с отдельным разбором. Проверка черновика таймера учитывает разные API Unity, включая `Invoke` и корутины; наличие черновика не означает его компиляцию или запуск. Результаты версий проверочного кода нельзя напрямую смешивать в один показатель.

Для облачных моделей `:cloud` добавлена [совместимость протокола Ollama](custom-api.md#облачные-модели-через-установленную-ollama). Для потоковых запросов действует ограниченный повтор до первого полученного фрагмента. Эти изменения относятся к адаптеру модели, без готовых планов конкретного мира, меню или меша.

Финальный архив прошёл 678/678 проверок Edit Mode из исходников и из TGZ в копии пользовательского URP-проекта; 26 Play Mode прошли, 2 сетевых теста пропущены. В окончательном прогоне Beam полностью прошли 4 из 6 запросов. Рельеф с пещерой и поиск навыков выполнили предметные условия, но завершились ошибкой получения ответа провайдера и не засчитаны как полный успех.
