# ScenePilot 1.8.1 — preview

ScenePilot 1.8.1 improves recovery from failed tool calls, retains useful compiler and scene evidence, and distinguishes researched explanations from project changes. The frozen RC20 package completed the validation below.

## Changes

- **Recovery instructions follow the active protocol.** Native function calls and JSON fallback now receive consistent instructions before inference and audit recording. Recovery retains the actual tool list, bounded errors and measured observations. Nine regressions cover both directions; validation, repeated-read controls and manual-edit protection remain in place.
- **Accepted diagnostic stages can advance the recovery budget.** A successful review of a new read-only diagnostic stage is retained across replanning. New plans, verification jobs and failed reviews do not reset the budget. This fixes an early stop after an accepted diagnostic stage without making repeated reads count as implementation.
- **Failed C# retains concrete source evidence.** Bounded excerpts around actual compiler line and column locations, together with the source hash, survive fresh planning. Rollback keeps the root JSON result intact and adds separate completion, error and scope fields; Undo behavior is unchanged.
- **Explanations do not require world edits.** A persisted task purpose distinguishes Ask/explicit explanations from implementation plans awaiting approval. Negated mentions of scripts, players or object counts no longer invent authoring checks for explanations. Plan approval retains its implementation criteria; actual failed verification and preservation checks remain visible. RC20's full Editor suite passed all 17 purpose cases.
- **Optional discovery failures can recover from later observations.** A read-only explanation can complete after a later accepted batch returns actual source data successfully. Earlier failed receipts remain intact. Concrete read, verification, compilation and mutation failures, failed explicit checks and unsuccessful batches are not waived by this policy. Its 12 Editor regressions passed; the rule has no URL- or query-specific branches.
- **Recovery keeps useful evidence.** Measurements and failed checks survive reload and replanning. Repeated reads and new verification job IDs do not count as implementation progress. Targeted inspection and scene capture stay available during recovery.
- **Geometry inspection separates collision and shading data.** Mesh topology, face orientation and physical ray coverage are reported alongside actual stored vertex-normal counts and lengths. Six new regressions cover cancelled, missing and unusual normals plus reading limits. Diagnostics stay neutral for intentional unlit/custom data and do not repair the scene or weaken checks.
- **Material checks use the actual render pipeline.** The agent receives quality/project pipeline settings, observed shaders and known compatibility problems before authoring materials and reviewing the result. Unknown custom combinations remain unclassified. Inactive warnings do not automatically become new task requirements.
- **Input probes report delivered events.** Runtime checks record events received for their virtual keyboard and mouse, including update types. Temporary background execution and input settings are restored afterward. Event counts alone do not prove that a button, controller or game mechanic worked.
- **Repeated saves keep the same destination.** A task can save its current, previously observed generated scene without creating numbered copies. Different destinations retain Save As behavior, and unrelated existing files remain protected.
- **Admitted light changes are prepared before sealing.** New Lights and admitted changes to Light settings or transforms receive required URP data before the checkpoint is sealed, so ordinary Scene View rendering does not introduce that late initialization. The helper leaves untouched Lights and their existing data alone.
- **Scene capture cleans up a known URP side effect.** Rendering can lazily add additional-light data to existing Lights. Capture now removes only data created by that observation, preserves pre-existing data, and releases temporary render resources on failure. Regression tests check clean scene state, checkpoint continuation, prefab overrides and continued detection of real manual edits.
