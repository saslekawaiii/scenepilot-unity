# Устройство и границы агента WorldWeaver 1.2

Это подробная справка к рабочей реализации 1.2.0. [Программный снимок 1.2](../results/integration-1.2-sixth-summary.json) прошёл 300 EditMode и 9 PlayMode проверок без внешнего inference; это не итог свободной беседы с моделью. Итоговый релиз фиксируется отдельно; сохранённые показатели 1.1 не присваиваются новому коду. Краткий запуск — в [README](../README.md), инструкция пользователя — в [руководстве пакета](../Packages/com.worldweaver.toolkit/Documentation~/index.md).

## Проверка задачи и работа с C#


У сообщения сохраняются исходный запрос, извлечённые требования, результаты проверок, ссылки на задания Unity и открытые вопросы. Модельное `complete:true` само по себе не подтверждает успех.

Базовая схема описывает инструменты, а `AgentTaskSchema` дополнительно сужает прямо запрошенное создание нового мира: распознанные количества и размеры становятся обязательными singleton-значениями; на начальном этапе без созданного world scope допускается не более одного действия. Общий конечный RU/EN-распознаватель используется и для выбора инструментов, и для специализации схемы. Добавление NPC или трёх источников света внутри существующего мира не получает это ограничение нового мира. Отрицание создания и обстоятельство места тоже учитываются конечными правилами. Нераспознанная формулировка следует обычному отбору инструментов; общий языковой анализ не заявляется. [Программные проверки этого различия](../results/world-intent-1.2-verification.json) используют управляемый провайдер и не доказывают качество планирования реальной LLM.

Host повторяет буквальные условия перед изменением сцены и отклоняет дублирующий scatter указанных декораций. Матрица 33/33 базовой схемы сама не оценивает эту стратегию или качество LLM. Для сокращения контекста начальный набор инструментов отбирается по словам запроса. При незавершённом ответе с пустыми действиями набор может расшириться в следующем доступном раунде, сохраняя разрешения и общий бюджет. Независимый проверяющий код сопоставляет распознанные буквальные условия с реальной сценой: числа объектов, размеры Terrain, наличие требуемых компонентов и объявленные связи NavMesh. Это конечный набор RU/EN-шаблонов, а не полное понимание любого задания. Наличие Player/Quest-компонентов не доказывает прохождение игры; художественное качество автоматически не оценивается.

Новый C# сначала появляется как **черновик**. Для существующего `Assets/...cs` поддержана точечная правка: предварительное чтение, SHA-256 текущего файла, ровно одно совпадение заменяемого текста и повторная проверка перед записью. Такой план содержит до четырёх файлов; patch принимает UTF-8 C# до 96 КиБ. Изменённый вручную файл не должен затираться устаревшим патчем.

После **Применить** Unity импортирует файлы, а реальные compiler events и ошибки добавляются в историю. Автоматическое исправление ограничено двумя видами коротких exact-match патчей в уже просмотренных файлах: добавить пропущенную точку с запятой по CS1002 либо заменить неизвестный идентификатор по CS0103 на явно запрошенный числовой литерал, если в исходном запросе указано одно различимое число. Нужны настоящая диагностика той же строки/позиции и совпадение хеша записанного исходника. Такой путь разрешён не более чем на двух продолжениях; все прочие изменения кода снова требуют просмотра. Всего у задачи не более трёх продолжений. Применённый C# имеет обычные права кода Unity; фильтр команд и просмотр не являются песочницей.

Подключение компонента выполняется отдельным шагом после подтверждённой компиляции текущего исходника. Исходник остаётся в истории как снимок; это не замена текущему файлу. Для сохранённых импортов новых скриптов доступна **Вернуть предыдущий код**; для восстановления целого запроса, включая патчи, используется контрольная точка задачи.

Инструменты могут запустить настоящие EditMode/PlayMode-тесты с явным фильтром, измерение локального вращения Y в Play Mode или Development build для активной платформы и сохранённых enabled-сцен Build Settings. Задания выполняются внутри Unity, результаты сохраняются отдельно. Изменение списка сцен сборки — отдельный просмотренный план: от одной до восьми существующих Assets-сцен, с контрольной точкой. Пустой, skipped или inconclusive набор не считается успешным тестированием. Компиляция, успешный build и измерение одного вращения подтверждают разные свойства; ни одно из них не заменяет полную проверку игрового задания. Shell, произвольный запуск методов, установка модулей и публикация Player не предоставляются.

## Как ограничивается контекст модели

Проверяющий код извлекает конечные буквальные RU/EN-условия, включая размеры в запросе «Создай долину 160×160 метров» и высоту в «Уменьши высоту существующего рельефа до 24». Это распознавание конкретных формулировок; неоднозначные количества остаются открытым вопросом. Высота NPC, игрока или кнопки не должна становиться требованием к Terrain.

В модельную проекцию задачи передаётся число исходных объектов, а не весь список их стабильных ID. Полные ID остаются у host для проверки сохранности объектов; механизм восстановления не изменяется. Обычные деревья, дома и камни в снимке сцены агрегируются; выбранные, однозначно названные и scope-объекты получают приоритет. Недостающие детали доступны через `find_scene_objects` и `inspect_object`. Эти сокращения не изменяют host-условия проверки и разрешения на действия.

| Часть запроса | Ограничение в текущем коде |
| --- | --- |
| Снимок сцены | Целевой объём 3000 / 4000 / 6500 символов для Быстро / Баланс / Глубоко. Это мягкий предел: обязательные идентичности сохраняются и могут превысить его с отдельным признаком. |
| Предыдущие реплики | До шести; текст каждой обрезается после 800 символов. |
| Результаты инструментов текущей задачи | До 10 000 символов сериализованных записей; summary одной записи до 1800. |
| Текстовые evidence в проекции задачи | Общий бюджет 1400 символов для этих полей; до восьми последних записей по 160, evidence одной проверки до 400. Остальные поля задачи в этот предел не входят. |
| Design memory | Лексический отбор в бюджет 2500 символов. |
| Справочные навыки | До трёх; начальный бюджет 4000 символов, настройка 1000–12 000. |

Это пределы отдельных частей, а не гарантия общего числа токенов или скорости модели. Исходный запрос, схема, обязательные идентичности и compiler context тоже занимают контекст. [Программная проверка сокращения контекста](../results/prompt-compaction-1.2-verification.json) подтверждает ограниченные инварианты и сохранность host-baseline; улучшение качества LLM или времени выполнения из неё не следует.

## Восстановление и локальные данные

Перед первым изменяющим шагом создаётся контрольная точка запроса; после шага фиксируется его write set. Она включает `Assets`, `ProjectSettings`, два package manifest-файла и рабочее состояние загруженных сцен. Восстановление возвращает изменённые этим запросом файлы и сцены только при отсутствии конфликтов с последующими правками. Продолжение тоже останавливается, если проект изменился между шагами. Это не резервная копия всего компьютера или всех каталогов проекта.

Ограничения checkpoint: до **300 МиБ**, **20 000 файлов**, **1–8 загруженных сцен**; несколько сцен должны быть сохранены, одна untitled-сцена поддерживается. Prefab Mode, baked lighting, symlink-пути и выполнение во время Play Mode не поддерживаются. `Library`, веса моделей, история в `UserSettings`, прочие исходники `Packages` и внешние побочные эффекты кода в snapshot не входят. Обычный **Undo Unity** остаётся отдельной командой и может отменить последнее ручное действие; он не равнозначен checkpoint.

| Данные | Хранилище |
| --- | --- |
| Беседы, задачи, требования и design memory | `UserSettings/WorldWeaverChat/<session>.json` |
| Контрольная точка и content-addressed backup | `UserSettings/WorldWeaverCheckpoints/<id>/` |
| Задания Unity, XML тестов, измерения | `UserSettings/WorldWeaverAgentJobs/` |
| Управляемые копии изображений | `UserSettings/WorldWeaverImages/` |
| Несекретные подключения своих моделей | `UserSettings/WorldWeaverModels/connections.json` |
| Журнал импортов новых C# / состояние компиляции патча | `UserSettings/WorldWeaverChatCode/` / `UserSettings/WorldWeaverPatchCompilation.json` |
| Созданные ассеты | `Assets/WorldWeaverGenerated/` |
| Player build | `Builds/WorldWeaver/<job>/` |
| Сохранение игрового мира | `Application.persistentDataPath/WorldWeaver/<WorldId>.json` |

После domain reload GUI-координатор читает ожидающую задачу и продолжает её только после окончания compilation/import/Play Mode и задания Unity. Имеющийся `PendingPlan` сам не применяется. Долговечная запись результата задания не гарантирует перезапуск потерянного queued test/build после рестарта редактора. Конечные состояния включают отказ, отмену и прерывание; отсутствие callback не считается успехом. Автоматический координатор отключён в batch mode.

Design memory — компактные заметки этой беседы с источником сообщения: до 128 записей, с ограниченным лексическим отбором в контекст. Это не общая векторная база проекта и не память игровых NPC.

## Навыки, изображения и потоковый ответ

В пакет входит библиотека **60 справочных MD-навыков**, адаптированных из закреплённых MIT-источников с лицензиями и SHA. Панель **Навыки** показывает каталог, поиск, содержание и настройки. В текущем чате по запросу выбираются до трёх подходящих записей; начальный бюджет — 4000 символов. Вся библиотека в контекст не передаётся. Дополнительные каталоги задаются явно; внешние записи считаются недоверенными справочными данными. Markdown не исполняется, не обучает веса модели и не даёт новых инструментов или разрешений. [Источники, лицензии и формат](skills/README.md).

Через **+** можно приложить до трёх PNG/JPEG или захватить вид реальной камеры сцены. Файл до 8 МиБ проверяется и нормализуется в отдельную копию: не более 1280 пикселей по стороне и 2 МиБ. Исходный файл пользователя не переписывается. Для отправки изображений нужна выбранная локальная модель с поддержкой vision; при отсутствии этой возможности запрос с изображениями отклоняется. В `-nographics` снимок не создаётся. Поддержка входа не доказывает правильность визуального вывода модели; аннотирование, видео и произвольное чтение файлов этим механизмом не предоставляются.

Ollama использует поток NDJSON: в чате постепенно показывается текст поля `reply`. Частичные токены не выполняют инструменты; изменения начинаются только после получения, разбора и валидации полного `EditorPlan`. Прерванный поток не переигрывается скрыто. Для остальных провайдеров потоковая доставка этим кодом не обещается.

## Деревня, NPC и игра

Готовый игровой пример открывается через **Tools → WorldWeaver → Создать играбельную деревню**. Команда предлагает сохранить текущие изменённые сцены, создаёт новую, сохраняет её под уникальным именем в `Assets/WorldWeaverGenerated/Scenes` и добавляет в Build Settings, сохраняя прежние записи и их флаги. Затем нажмите Play. Этот путь выполняет заранее заданный план без LLM; его результат не является модельной генерацией по свободному запросу.

`create_world` создаёт параметрический Terrain и декорации. `create_village` — отдельный специализированный процесс: терраса, дома и входы, площадь, дороги, именованные места, северные ворота, NPC, реальная NavMesh, необязательные игрок и квест доставки письма. Это локальная процедурная геометрия и примитивы, не генерация ригов или художественных 3D-моделей. Один запрос создания деревни не требует второго `create_world` поверх неё.

В Play Mode игрок управляется **WASD**, правой кнопкой мыши поворачивает камеру, **E** взаимодействует с близким участником квеста. Есть экранные действия, часы и кнопки сохранения/загрузки. Контроллер использует стандартный Unity Input Manager. Квест выдаёт реальное письмо, проверяет расстояние и инвентарь, один раз начисляет награду; этот путь не требует LLM. Разговор с NPC остаётся отдельным модельным процессом со scoped retrieval и проверяемыми действиями.

Маршруты используют именованные `WorldPlace` и проверенные полные NavMesh-пути. Часы управляют воротами с collider/carving и дневной/ночной целью NPC. Недоступная основная цель остаётся отмеченной как blocked, даже если NPC идёт к fallback. Проверка declared connections не доказывает доступность каждой точки произвольного окружения. Обновление Terrain может повторно привязать явно отмеченные объекты к поверхности и перестроить NavMesh; неотмеченные ручные объекты не получают такую гарантию.

Сохранение относится к тому же `WorldId` и существующим идентичностям: позиции и инвентари акторов, scoped память NPC, отношения, стадия квеста, часы и журнал событий. Это не сериализация произвольной сцены или генерация нового мира из save-файла. Память NPC ограничена 32 документами, общий журнал — 128 событиями; сохранение/загрузка ожидают окончания разговоров. Версия и содержимое проверяются до применения.

Каталог prefabs читает существующие `Assets/...prefab`, их bounds, компоненты и материалы. Размещение не скачивает ресурсы. Prefab с пользовательскими скриптами требует явного разрешения и просмотра плана; лицензия исходного ассета проверяется отдельно. Новая 3D-генерация, skinning, rigs и animation authoring не заявляются.

Прежние WORLD/NPC/KNOWLEDGE/MODELS/DEBUG доступны через **Advanced Inspector**. **Create Demo in New Scene** сохраняет отдельную демонстрацию ядра 1.0. Эти команды не являются новым chat-вариантом деревни.

## Провайдеры и границы

Локальный inference не требует покупки API. Необязательный Pollinations Classic использует `https://text.pollinations.ai/openai`, псевдоним `openai-fast`, фактическую модель GPT-OSS 20B в сохранённых опытах. В проверенном 31.10.2026 официальном адаптере — один бесплатный ответ за **45 секунд на IP** и **1500 выходных токенов**; клиент выдерживает 46 секунд между началами. Доступность бесплатного сервиса не гарантируется. [Закреплённый исходник Classic](https://github.com/pollinations/pollinations/blob/73311dad9465c7ddd0ceb9cdc0f2ab8b171f6dbb/text.pollinations.ai/cloudflare-cache/src/origin.js#L24-L27).

Среди HTTP 402 повторяется только распознанный `FREE_LIMIT` в пределах профиля, с fallback 46 секунд при отсутствии Retry-After. Обычные платёжные ошибки и HTTP 400 автоматически не повторяются; адаптер не выполняет оплат. Classic использует текстовый JSON-контракт и C#-валидацию, а не обещание enforced schema сервера. Узкая нормализация одной пропущенной финальной скобки и явного readonly-текста сохраняет исходный ответ отдельно; она не додумывает команды или поля.

Облачный запрос передаёт отобранный контекст проекта внешнему сервису. Профиль хранит имя переменной окружения, а не секрет. Свои Ollama/OpenAI-compatible подключения добавляются без кода через форму чата; [порядок настройки и срок жизни ключа](custom-api.md). В конфиг UserSettings сохраняются только несекретные поля и имя переменной окружения; секреты не должны попадать в assets, URL, логи или Git. Распознавание некоторых секретов в тексте не доказывает их универсального обнаружения. В старых опытах OpenAI был недоступен из-за баланса, Groq вернул 403; успешный inference для них не заявляется.

Голос, PDF ingestion, произвольный shell, установка зависимостей, внешняя публикация и полная замена разработчика в набор возможностей не входят.
