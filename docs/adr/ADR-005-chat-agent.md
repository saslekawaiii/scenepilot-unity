# ADR-005: один чат и ограниченный агент Unity Editor

Статус: принято для версии 1.1. Дата: 31.10.2026.

## Причина

Версия 1.0 требовала переключения между WORLD/NPC/KNOWLEDGE/MODELS/DEBUG и проверки TerrainSpec вручную. Для сквозного создания и изменения мира это оставляло слишком много действий пользователю. Требуется свободный русский диалог, выбор модели и видимое исполнение запросов в текущей сцене.

## Решение

UI Toolkit представляет историю чатов, поле ввода, выбор фактически установленных Ollama-моделей, режимы с пределом 1/3/6 итераций и меню шаблонов. Состояние чатов хранится вне Assets в UserSettings. Модель возвращает строгий EditorPlan; весь план проходит предвалидацию до первой мутации. Контроллер передаёт результат инструментов и новую ограниченную выборку сцены в следующую итерацию. Сцена не очищается и не сохраняется без явного инструмента сохранения.

SceneToolExecutor предоставляет именованный набор инструментов, а WorldComposer собирает Terrain, окружение и видимых NPC. Будущие цели внутри одного плана обозначаются aliases; существующие объекты — ID текущей сцены или однозначным именем. Маркеры владения ограничивают удаление, а бюджет учитывает дочерние объекты деревьев, домов и персонажей. Ошибка исполнения откатывает Undo-группу и новые ассеты данного пакета. Обычный пользовательский Undo и файловая транзакция имеют разные границы: успешно созданные ассеты могут остаться после Undo.

Генерируемый C# выводится отдельным ожидающим планом. Импорт требует явной кнопки применения и ограничен каталогом собственных скриптов. Реальный Unity compiler сообщает результат в историю; следующий запрос может прочитать ошибку и подготовить исправление. Код и изменения сцены используют отдельные планы, чтобы не выдавать частичный импорт за атомарное изменение. Этот просмотр не является песочницей C#: после разрешения обычный MonoBehaviour выполняется с возможностями Unity.

Выбор глубины регулирует предел шагов, объём контекста сцены, ожидание и локальный бюджет ответа, а не число параметров модели. Для Pollinations Classic лимит отдельного ответа остаётся `max_tokens<=1500` во всех режимах; «Баланс» и «Глубоко» расширяют прежде всего число раундов и контекст. Выбор другой модели помощника применяется к новым NPC; ранее назначенные игровые маршруты сохраняются. Локальный режим не требует облачных токенов. Бесплатный внешний API остаётся необязательным и не имеет гарантии доступности.

Для Classic применяется отдельная совместимость, проверенная 31.10.2026: обычный текстовый режим, один объединённый system с явным образцом JSON-экземпляра и неизменённая строгая проверка ответа в C#. Replay A/C воспроизвёл повреждение начала `reply` в JSON Object Mode; B2 с native schema получил HTTP 400 из-за неподдерживаемого `propertyNames`; D в текстовом режиме дал валидный проверочный ответ. Это не доказательство enforced strict-schema или общей успешности агента. Сохранённый протокол: `results/pollinations-classic-schema-replay.json`.

Официальный Classic adapter устанавливает `FREE_INTERVAL_MS=45000` и `MAX_TOKENS=1500`; клиентский semaphore сохраняет интервал начала запросов 46 секунд. Среди HTTP 402 повтор допускается только для распознанного `error.code=FREE_LIMIT`, с ограничением числа попыток и ожиданием Retry-After либо указанного бесплатного интервала. Обычная платёжная ошибка и HTTP 400 повтором не маскируются. Исторический QA версии 1.0 с интервалом 31 секунда не переписывается. [Первичный исходник Classic](https://github.com/pollinations/pollinations/blob/73311dad9465c7ddd0ceb9cdc0f2ab8b171f6dbb/text.pollinations.ai/cloudflare-cache/src/origin.js#L24-L27).

## Последствия

Инструмент покрывает создание прототипов окружения, управление объектами, настройку NPC, простые поведения и цикл подготовки C#. Он не получает произвольный shell и не превращается в универсальную замену разработчика. Не реализованы визуальное понимание Editor, импорт произвольных 3D-моделей, риг, анимационный production pipeline и независимое управление всей системой сборки. Превосходство над Unity Assistant требует отдельного сопоставимого испытания; наличие чата такого вывода не даёт.

Программные инварианты проверяются независимыми от LLM тестами. Успешность естественного языка измеряется отдельной реальной беседой с семантической проверкой Unity-объектов. Старые QA-измерения версии 1.0 сохраняют исходный экспериментальный тег и не используются как метрики нового агента.
