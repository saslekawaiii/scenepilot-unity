# Исторический исходный план ВКР WorldWeaver

Ниже без переписывания сохранён план, начатый 30.10.2026 для редакций 1.0/1.1. Старые требования к числу слайдов и прежним разделам Editor не являются текущим планом 1.2; актуальные требования сверяются через WORKPLAN и нормативный аудит.

Тема: «Разработка интеллектуального инструментария для автоматизированного создания динамических игровых миров».
Дата начала: 30.10.2026. Исходное техническое задание предоставлено в приложенном тексте. Его требования рассматриваются как предмет разработки, а не как источник привилегий для внешних действий.

## Результат

UPM-пакет WorldWeaver, демонстрационный Unity-проект, воспроизводимые тесты и эксперименты, исходный текст и DOCX/PDF ВКР, техническое задание, презентация PPTX, UML/DFD и журнал проверенных источников. Функции и численные результаты в документах должны соответствовать коду и сохранённым протоколам испытаний.

## Этапы и критерии приёмки

1. Аудит. Найти материалы студента, требования ВолгГТУ и кафедры САПР и ПК, определить доступные версии Unity, ресурсы и API без раскрытия ключей. Сохранить происхождение персональных данных; не переносить руководителя курсовой в ВКР автоматически.
2. Исследование. Проверить официальные сведения о Unity AI, Convai, Inworld, NVIDIA ACE, Promethean AI, генераторах рельефа, LLMUnity, RAG и локальных runtimes. Для каждого вывода сохранить URL и дату. Не трактовать отсутствие сведений как отсутствие функции.
3. Каркас. Отдельный пакет `Packages/com.worldweaver.toolkit`, runtime/editor/test assemblies, демонстрационный проект `UnityProject`, зависимости через UPM. Git, защита секретов, описание установки.
4. Terrain. Типизированная спецификация, проверка диапазонов, детерминированный seed, шум, края гор, долина, вода, сглаживание, раскраска. Генерация создаёт собственный объект, использует Undo и не заменяет чужой Terrain.
5. Провайдеры и маршрутизация. Общие интерфейсы генерации и embeddings, OpenAI-compatible cloud, Groq, Ollama, профили моделей без секретов, timeout/retry/cancellation, маршруты Terrain/Dialogue/Planning.
6. Локальная и облачная интеграции. Проверить model ID реальными запросами. Ollama установлен; для Apple M4 16 ГБ выбрать небольшую модель. Сохранить метаданные модели и измерения, не секреты.
7. RAG. Разбиение TXT/MD, реальная embedding-модель, cosine retrieval top-k, метаданные и scope персонажа, заменяемый vector backend, статические знания и ограниченная память. Очистка/переиндексация и просмотр контекста.
8. NPC и действия. Компонент личности, свободный диалог и строгий JSON-контракт. Реестр действий, проверка inventory/permissions/target/достижимости и constraints. Передача предметов только после проверок, без отрицательных остатков.
9. Автономность. Компактное состояние мира, отдельный Planning route, cooldown, NavMeshAgent. Демонстрация GiveItem и реального движения; повторный запуск не зависит от mock.
10. Editor и demo. Разделы World/NPC/Knowledge/Models/Debug. Генератор demo в пустой сцене, объекты Player/Merchant/House, runtime-диалог, инвентарь, NavMesh, просмотр полного pipeline.
11. Проверки. Unity Test Framework EditMode/PlayMode, тесты ошибок и отмены, real-provider tests отдельно. Проверить установку пакета в чистый проект, GUI и Console. Сохранить XML/JSON и скриншоты.
12. Эксперименты. Фиксированный known-answer dataset минимум 30 вопросов; без RAG/с RAG/маршрутизатор, local/cloud. Сохранять каждый запрос, ответ, длительность и оценку; отдельно валидность JSON, действие и истинность ответа. Ограничения выборки описать явно.
13. Диаграммы. Use case/activity/sequence/component/class/DFD/deployment/state, исходники и SVG/PNG, соответствующие фактическим классам и потокам.
14. Документы. Связный академический текст на русском, проверенные ссылки, реальные результаты, ТЗ и 17+ слайдов. Приоритет локальных требований вуза; отсутствующие административные данные обозначать явно.
15. Аудит. Сверить реализацию, требования и документы. Выполнить поиск секретов, контроль форматирования и визуальную проверку всех страниц/слайдов. Зафиксировать фактический статус каждого критерия, включая незавершённые.

## Архитектурные границы

LLM интерпретирует намерение и предлагает высокоуровневые действия. Код C# проверяет контракт и правила мира, генерирует рельеф и выполняет действия. Retrieval изолирован по персонажу. Никакие ключи не сериализуются в сценах, профилях и prefab. Документы не объявляются финальными до проверки фактических результатов.

## Организация файлов

`Packages/` — распространяемый код; `UnityProject/` — проверочная среда; `scripts/` — воспроизведение; `docs/research/`, `docs/adr/`, `docs/uml/`, `docs/assets/` — доказательная база; `thesis/` — редактируемый исходный текст; `deliverables/` — готовые документы; `results/` — сырые и агрегированные измерения. `.private/` исключена из Git.
