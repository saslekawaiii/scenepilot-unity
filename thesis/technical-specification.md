# 1 Введение

Наименование изделия — WorldWeaver Intelligent World Toolkit. Изделие представляет собой UPM-пакет для автоматизированного формирования рельефа и настройки интеллектуальных NPC в Unity. Языковая модель интерпретирует описание или предлагает действие; изменение сцены выполняется детерминированными C#-компонентами после проверки.

Настоящая редакция отражает фактическую область поставки. Исходный документ от 30.09.2026 использован как основание функциональных требований и графика. Голосовые интерфейсы, извлечение PDF и постоянное сохранение памяти не включены в подтверждённые функции.

# 3 Назначение разработки

Функциональное назначение — сократить число отдельных интеграций, необходимых для подготовки Terrain, базы знаний и модельного NPC в экспериментальном Unity-проекте. Сокращение трудозатрат выражается как цель изделия; численный процент экономии не устанавливается без отдельного измерения.

Эксплуатационное назначение — использование разработчиком Unity при прототипировании мира, демонстрации свободного диалога и исследовании высокоуровневых действий. Изделие не предназначено для произвольного исполнения сгенерированного кода и не предоставляет модели прямой доступ к Unity API.

# 4 Требования к программному изделию

## 4.1 Функциональные требования

| ID | Требование | Реализация и критерий |
|---|---|---|
| FR-01 | Установка и интерфейс | UPM-пакет, меню Tools, пять разделов Editor |
| FR-02 | Провайдеры | ILLMProvider, Ollama и OpenAI-compatible adapters |
| FR-03 | Оркестрация | Отдельные Terrain, Dialogue и Planning routes; embedding-provider |
| FR-04 | Terrain по описанию | LLM формирует TerrainSpec; C# вычисляет heightmap |
| FR-05 | Повторная генерация | Seed, диапазоны параметров и Undo собственного Terrain |
| FR-06 | Личность NPC | Роль, характер, биография, цели и сериализуемые ограничения |
| FR-07 | Индивидуальный RAG | TXT/MD/JSON, chunks, embeddings, scope, top k и reindex |
| FR-08 | Память | Разговорные и эпизодические документы текущего сеанса |
| FR-09 | Свободный диалог | Текстовый ввод и структурированное решение; голос вне версии |
| FR-10 | Контекст мира | KnownEntities, inventory, state и IWorldContextSource |
| FR-11 | Последствия разговора | GiveItem после проверки, реальные изменения обоих Inventory |
| FR-12 | Реестр действий | IGameAction и Register без изменения router |
| FR-13 | Автономность | Planning по cooldown; MoveTo/Follow/Flee через NavMeshAgent |
| FR-14 | Валидация | JSON-контракт, permissions, target, amount и projected inventory |
| FR-15 | Диагностика | Raw JSON, route, retrieved, latency, usage и action report |
| FR-16 | Обработка отказов | Timeout, cancellation, bounded retry и контролируемая ошибка |

Для Terrain поддерживаются равнинные и холмистые поверхности, горный край, центральная долина и визуальная водная зона. Настраиваются seed, физические размеры, разрешение, октавы, persistence, lacunarity, глубина долины, уровень воды и сглаживание. Значение resolution выбирается из 33, 65, 129, 257 и 513.

Для NPC поддерживаются GiveItem, TakeItem, MoveTo, Follow, Flee, Wait, Talk и Interact. Наличие обработчика не означает предоставления разрешения: каждое действие должно входить в AllowedActions. TakeItem дополнительно требует явного флага. Максимальное количество передачи за решение задаётся числом и не выводится из свободного текста personality.

RAG обязан ограничивать доступ по CharacterId до сравнения векторов. Статические знания, эпизодическая и разговорная память различаются MemoryKind. Разговорная и эпизодическая память ограничивается 32 документами текущего сеанса. Индекс и память в данной версии не сохраняются между запусками игры.

## 4.2 Требования к надёжности

Ошибка модели или сети не должна приводить к выполнению непроверенной команды. Неверный target, недостаточный inventory и превышение бюджета отклоняются до инвентарных изменений. Пакет встроенных действий предварительно проверяется целиком на проекции инвентарей.

Сетевое обращение должно завершаться по timeout или cancellation. Повторы допустимы для ограниченного набора временных ошибок и ограничены профилем. Тело ответа ограничивается двумя мебибайтами. Сырые provider-ошибки с возможными фрагментами credential не журналируются.

При отключении NPC активный запрос отменяется. В интерфейсе не должно быть скрытого переключения на mock после ошибки реального API. Mock используется только в автоматических тестах и обозначается как тестовый provider.

## 4.3 Требования к условиям эксплуатации

Основная проверенная среда — Unity 6000.3.27f1 LTS на macOS 15.7.4, Apple M4, 16 ГБ объединённой памяти. Дополнительно подтверждены компиляция и EditMode-тесты в Unity 2022.3.62f3. Другие версии и платформы требуют отдельных проверок.

Для локального режима требуется Ollama с моделями Qwen3.5 2B, qwen2.5-coder 7,6B и EmbeddingGemma. Размещение весов вне репозитория обязательно. После установки моделей основное локальное взаимодействие не требует внешнего LLM API, однако UPM-зависимости должны быть заранее получены.

Для бесплатного облачного режима требуется доступ к Pollinations Classic API. На дату испытания сервис ограничивает текстовые запросы одним за 30 секунд на IP и предоставляет best-effort доступ без SLA. Программный интервал составляет 31 секунду. Платёжные действия и автоматическое пополнение отсутствуют.

## 4.4 Требования к защите конфигурации

API-ключи не должны сериализоваться в сценах, prefab, ScriptableObject, тестовых fixtures или README. Профиль допускает только имя переменной окружения. Настоящий .env исключается из Git; .env.example не содержит значений. Перед передачей репозитория выполняется проверка на секреты.

Удалённые endpoints должны использовать HTTPS; HTTP допускается только на loopback. URL не должен содержать credentials, query и fragment. Автоматические HTTP redirects отключены. В runtime-клиенте с платным приватным ключом для реального продукта требуется доверенный серверный посредник; его реализация не входит в эту версию.

## 4.5 Требования к совместимости и расширению

Runtime-сборка не должна зависеть от UnityEditor. Новые inference backends подключаются через ILLMProvider, embeddings — через IEmbeddingProvider, vector backend — через IVectorStore, действия — через IGameAction. Расширение должно сохранять контракт Validate без побочного эффекта.

Произвольный rollback пользовательского action во внешней системе не гарантируется. Для таких действий разработчик должен проектировать собственный протокол подготовки, commit и компенсации. Текущая атомарная предварительная проверка относится к встроенному игровому состоянию.

# 6 Технико экономические показатели

В рамках данной поставки измеряются длительность TerrainGenerator, повторяемость по seed, качество retrieval, совпадение ответов с эталоном, валидность JSON и задержки. Стоимость использованных API-запросов равна нулю при соблюдении условий бесплатного сервиса. Стоимость оборудования, электроэнергии и труда не приравнивается к нулю.

Сравнение времени ручной подготовки и работы через инструментарий требует отдельного протокола с одинаковыми задачами и участниками. Такое исследование не подменяется субъективным утверждением об ускорении. Измеренные QA- и runtime-показатели приводятся в результатах ВКР.
