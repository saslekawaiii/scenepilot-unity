# Исходники новой редакции пояснительной записки

Тема: «Разработка интеллектуального инструментария для автоматизированного создания динамических игровых миров». Источники 00–06 и ТЗ полностью переписаны после проверки официальной программы ГИА нужного профиля. Нормативный аудит, URL, ограничения применимости и ошибки прежней редакции приведены в `docs/research/vkr-requirements-2026.md`.

Подтверждённые результаты версии 1.2 собраны в verification-cutoff-1.2-draft.json. R3 имеет 397 EditMode и 9 PlayMode; отдельный полный разговор R2 завершил семь приёмочных условий. Его просмотренный C# фактически импортирован, скомпилирован, подключён, возвращён и измерен на R3 без нового inference. Строгий visual-критерий не пройден; исход и частичная независимая оценка сохранены. Чистая установка R3 подтверждена. Исторические результаты 1.0/1.1 сохранены с версиями. Финальные DOCX/PDF редакции 1.2 находятся в deliverables: записка — 101 страница, в том числе 80 до приложений, ТЗ — 14 страниц. Все 115 страниц покрыты личной визуальной проверкой; 52 пункта содержания совпадают с PDF. Подлинная справка проверки заимствований и неизвестные административные реквизиты не изготовлены.

Редактируемые файлы — 00–06 и technical-specification.md. Файл «ВКР_полный_текст.md» создаёт сборщик. В исходниках ссылки используют постоянные ID исследовательского каталога; печатные номера формируются по порядку первого цитирования. Дополнительные первичные источники хранятся в supplemental-sources.json, уточнения библиографического описания — в source-overrides.json. Не следует вручную заменять ID в исходниках на номера из отрендеренного PDF.

Сборка использует `scripts/build_documents.py`. Флаг `--sources-only` обновляет полный Markdown без DOCX/PDF. Флаг `--draft` создаёт два DOCX в `.private/draft-vkr2026`; каталог можно указать через `--output-dir`. Обычная финальная сборка заблокирована, пока content_final и metrics_final в build-status.json не подтверждены по действительным результатам. Этот файл описывает статус выпуска, а не заменяет испытания.

Скрипты `scripts/enrich_thesis.py`, `scripts/finalize_thesis_text.py` и `scripts/research_catalog.py` относятся к исторической подготовке редакции 1.1. Их нельзя запускать для пересборки редакции 1.2: они перезаписывают главы или исследовательский каталог прежними данными. Для 1.2 используется только описанный выше сборщик и `scripts/map_document_pages.py` для проверки фактической пагинации.

Официальные титул и двухстраничное задание сохранены неизменными в templates. Заполняются копии только по документированным слотам. Неизвестные руководитель, приказ, код кафедры, срок и подписи остаются пустыми. Дата плана 2025 года не доказывает принадлежность студента к этому набору. Реквизиты необходимо сверить с официальным заданием перед подачей.

Тело записки: A4, поля слева/справа/сверху/снизу 30/10/15/20 мм, Times New Roman 14 пт, интервал 1,5, абзац 15 мм. Титул и задание сохраняют свои официальные макеты, входят в пагинацию и не имеют печатных номеров. Русская и английская аннотации расположены после задания. Содержание имеет не более двух уровней. Полное ТЗ включается в приложение из того же файла, который формирует отдельный документ.

При новой сборке требуется отрендерить оба DOCX, построить карту страниц, повторить сборку с заполненным содержанием и проверить каждую конечную страницу. В проверенной редакции до приложений 80 страниц, введение занимает 3, заключение 2; все три предела программы ГИА соблюдены. Реальный Times New Roman подтверждён по встроенным PDF-шрифтам; две редактируемые формулы используют отдельные математические шрифты. На macOS сохранён отдельный fontconfig в docs. Шрифтовые файлы не распространяются. Команды, версии, хеши и границы проверки сохранены в `results/document-pdf-render-1.2.json`, `results/document-rebuild-1.2.json` и `results/document-qa-1.2.json`.

Нельзя считать отсутствие обрезки доказательством соответствия методичке. Помимо визуального контроля проверяются структура, поля, абзац, нумерация источников, совпадение ТЗ, сохранность шаблонов и связь результатов с версиями кода. Финальный PDF экспортируется из точной проверенной версии DOCX.
